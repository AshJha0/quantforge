# ADR: Public API style across the four languages

## Status
Accepted for stage F (plan 13.2, item E4). The cross-language name map is ruling F-5 in `specifications/stage-f-rulings.md`.

## Context

The four libraries were built clean-room from the specs, so each chose its own public names. The CLI contract kept them interchangeable at the JSON boundary, but a reader who moves from the Python API to the Java API has to guess. The 2026-11-09 review (item E4) also found inputs whose unit is not in their name, option sides passed as strings, and types whose thread safety is not stated. Units are where quant code fails quietly: a rate in percent passed where a decimal is expected still returns a number. `architecture/numerical-standards.md` already asks for explicit units at public boundaries; this ADR makes that checkable.

## Decision

**1. One name map, generated.** `specifications/name-map.json` is generated by `tools/gen_name_map.py` from the operation tables in the specs. For operation `<domain>.<area>.<verb>`:

| Language | Public name |
|---|---|
| Rust | function `<area>_<verb>` in module `<domain>` |
| Python | function `<area>_<verb>` in module `<domain>` |
| Java | static method `<area>` + `PascalCase(<verb>)`, first letter lower case, in class `PascalCase(<domain>)` |
| C++ | function `<area>_<verb>` in namespace `qf::<domain>` |

Example: `bond.frn.price` is `quantforge::bond::frn_price`, `quantforge.bond.frn_price`, `Bond.frnPrice` and `qf::bond::frn_price`. Input keys keep their spec name, in camelCase in Java only. The file is the source of truth; the quality gate checks each language's public symbols against it (the E4 acceptance test). Do not edit the file by hand: change the spec and regenerate.

**2. Units in names.** A real-valued input or field that carries a unit names it: `_years`, `_days`, `_bp`, `_pct`. A bare rate or vol is a decimal (0.05 is 5%), as `specifications/cli-contract.md` and ruling C7 already say, and needs no suffix. A real input with a unit and no suffix is a name-map defect: the generator lists it under `unit_warnings`, so the list is the backlog, not a hidden exception. Dates are dates, never year fractions in disguise.

**3. Closed choices are enums, not strings.** Option side is `OptionType` with exactly `CALL` and `PUT`; pay or receive, delta type, interpolation and solve method follow the same rule. The spelling at the JSON boundary is the spec's upper-case string, and the library converts once, at the edge. An unknown value is `E_SCHEMA` at the boundary and cannot reach the maths.

**4. Validated constructors.** A public type checks its invariants when it is built and cannot exist in an invalid state: finite reals (rulings F-2 and F-4), strictly increasing pillar dates, bid at or below ask, discount factors above zero. A check fails with the spec's error code. A raw kernel that skips the checks for speed is allowed only when its documentation says "unchecked: caller guarantees finite inputs" (F-4), and the quality gate lists those kernels.

**5. Immutability and thread safety, stated per type.** Value types (quotes, trades, curve data, results) are immutable after construction: Rust structs without interior mutability, Python frozen dataclasses, Java records or final fields, C++ `const` members or types with no mutating public member. Each public type's documentation carries one line, in this form:

> Thread safety: immutable; safe to share between threads.

or, for anything with a cache or a builder:

> Thread safety: not safe to share; use one per thread. (reason)

A type without the line fails review. A cache that is a pure function of its inputs, such as the Python `lru_cache` on rebuilt curves in `sensitivities.py`, still needs the line, because the cache itself is shared state.

## Consequences

- A student can read one language's tutorial and guess the name in another (see [Tutorial 1](../../docs/getting-started/tutorial-1-swap.md)).
- Renames are breaking changes. They land in stage F, before v1.0, behind the name map, and the CHANGELOG lists each one.
- The `unit_warnings` list in the name map is open work and should only shrink.
- Thread-safety lines are documentation, not proof. Python property tests and the Rust type system check some of it; the rest rests on review.
