# W01: Repository, CLI and conformance

Stage A. Every implementation is a black box that reads a case and writes a result, so nothing else about it matters to conformance.

## Specification
`specifications/cli-contract.md`, `01-core/rulings.md`. Paths are under `specifications/` unless stated.

## Key formulas
Contract: `quantforge run`, `batch`, `version`, `operations`. Exit 0 ok, 2 result with status error, 64 usage, 70 internal fault.

Scalar comparison: `|a - e| <= absolute + relative * max(|a|, |e|)`, with the class from `conformance/tolerances/policy.yaml`.

The specs hold the full definitions and edge cases.

## Work
- [ ] Build the four commands, with a stable `E_*` code for every failure
- [ ] Implement the value encoding: u64 as strings, integers with no fraction, no NaN

## Four-language tasks

Each is done in a separate clean-room session, from the specs alone. Python is not the reference.

- [ ] Java 25: `java25/`
- [ ] C++26: `cpp26/`
- [ ] Python: `python/`
- [ ] Rust: `rust/`

Each language passes the named suites through `conformance/runner/runner.py`, and lists anything the spec left open in its `SPEC_QUESTIONS.md`.

## Acceptance
Golden suites: None of its own; the runner tests in `conformance/runner/test_runner.py`. All are in `datasets/golden/core/`, plus `rulings`. Expected values come only from `oracle/`.
