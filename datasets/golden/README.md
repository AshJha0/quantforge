# Golden results

A golden case is a stored case with an expected result obtained without any of the four implementations. They all come from `oracle/`; write none from an implementation. Two exceptions are stated here and tagged in [`docs/case-figures.md`](../../docs/case-figures.md#evidence-classes-per-stage):

- **Implementation-sourced.** `oracle/python/gen_stage_k_k8.py` imports the Python build and stores its output under the pinned reference scheme as the expected values of the 7 Bermudan ladder cases `k8_k-0001` to `k8_k-0007`; the other three builds agree to 1e-9 of the row scale, a blind re-derivation by a second AI lane matched, and three cases are within 1% of QuantLib (`verified_by` says so). The 2 `sorx_h` cases are the Python build's output kept as an agreement check across the builds, and are not counted as outside-checked.
- **Hand-derived.** Some cases are derived by hand from the spec (the generated count of value-checked cases resting on hand derivation only is in `docs/case-figures.md`). A hand case can share a misreading with the spec.

Each file holds `suite`, `spec`, `spec_version`, `generator`, `reviewer` and `cases`. Each case holds `case_id`, `operation`, `inputs`, `expected`, `tolerance_class`, `verified_by` and `tags`.

`reviewer` says "none: self-assessment; no second review (owner decision 2026-11-18)", which is the true state of every file. `verified_by` names the sources that agreed. A case with only hand or replay sources can share a misreading with the spec, as `oracle/README.md` explains. Which stage B suites have an outside oracle is in `specifications/stage-b-rulings.md`; stage C sources per suite are in `specifications/stage-c-rulings.md`.
