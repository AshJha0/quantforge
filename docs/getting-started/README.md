# Tutorials

Forty guided tutorials, each 10 to 15 minutes, that walk through what QuantForge already does. Each one starts from small synthetic data you can follow by hand, runs it in Python first, then sends the same operations to the Rust, Java and C++ builds, which print the same digits. Every number on every page is real output, and CI runs each page in all four languages and fails if a printed line differs (`.github/workflows/tutorial.yml`, `tools/check_tutorial.py`).

Each tutorial explains its results in the same order: the plain idea, the formal statement from the spec, then a worked example with a check you can do in your head. Each ends with notes for practitioners, common mistakes, what you just did, and references.

Do [Tutorial 1](tutorial-1-swap.md) first: it sets up the tools and builds the four command-line programs the others use. After that the order is free, except that Tutorial 6 introduces the Hull-White model that Tutorials 5 and 7 also use, and Tutorial 21 reruns the backtest of Tutorial 17 with costs, Tutorial 24 follows on from Tutorial 23, and Tutorial 29 reuses the inputs of Tutorial 25. Tutorials 27 to 32 go deeper into the stage J tools: each takes one question a researcher has to answer (what costs do, what a constraint costs, how strong a view is, how many trials a result survives, how much purging costs, when shrinkage helps).

## How the scripts work

Tutorials 41 to 43 (stage H wave 2) call the operations in process through the Python build (`quantforge_core.cli.main.run_case`, the entry point of the `quantforge` command) and stop if a result differs from its spec golden. Tutorials 36 to 40 (stage H) are hand checks: the operations are specified but not merged, so each page runs a short standard-library restatement of the spec's formulas on the golden inputs, in Python only, and shows the library call it will make from v0.10.0 without running it. Tutorials 2 to 16 and 23 to 32, 34 and 35 each run one script in `examples/tutorials/`. Tutorials 17 to 21 (stage I, hedging) instead show a short Python script on the page, calling `quantforge_core` directly, and a standard-library script per page, `examples/tutorial_hedge_17.py` to `examples/tutorial_hedge_21.py`, that sends the same cases to the Rust, Java or C++ build. The script calls operations by their names in `specifications/name-map.json` through one helper, `examples/tutorials/qf.py`: with no argument it uses the Python package in the same process, and with a command line it sends each case to that build's `batch` command (`specifications/cli-contract.md`). So one script, unchanged, drives all four implementations, and the page shows it in full; CI checks that the listing on the page equals the file.

```bash
uv run --project python python examples/tutorials/t4_credit.py          # Python
python examples/tutorials/t4_credit.py rust/target/release/quantforge   # Rust, Java or C++
```

To check a page yourself, as CI does: `python tools/check_tutorial.py --lang rust` (all pages) or add `--page docs/getting-started/tutorial-4-credit.md`. Pages 2 to 32 use the builds that page 1 makes, so check page 1 first in a fresh clone.

Scripts that send several cases at once and read their diagnostics, as in Tutorials 8 to 16, use `runner` from the same helper, the batch form of `connect`. Tutorial 1 is the first exception: to show what the library looks like from Python, its page calls the `quantforge_core` package directly, and a standard-library script, `examples/tutorial_swap.py`, sends the same three operations to the Rust, Java or C++ `batch` command. The hedging tutorials, 17 to 21, follow tutorial 1's form (ruling I-52): the page's Python block imports the `quantforge_core` modules, and `examples/tutorial_hedge_17.py` to `tutorial_hedge_21.py` send the same cases, built from the `examples/hedge_*_i.json` inputs, to the other builds. CI runs every page in each language it marks; Tutorial 22, a Python research tool, runs in Python only.
