# v0.8.3 release notes: fuzz fixes, Rust kill tests, stage J wave 1 spec documents

Released 2026-11-13 as a patch on top of v0.8.2 (branch `release-0.8.3`, one PR; the owner merges and tags). CLI contract unchanged (1.12.0). Language facts below were checked on the merged tree on one Windows machine with WSL (observed, local); CI results are in the PR.

## Known issue at the tag

**Rust mutation gate.** `mutation-report` samples 12 fresh Rust mutants per pull request run and needs all of them killed. This release adds kill tests for `var.rs` and `hedge.rs`, but the `hedge_solvers.rs` work is not done, so the check may be red until it lands in v0.9.0. It is not a required check.

## What this release is

Plain idea: three inputs found by fuzzing `main` made a build hang or crash; each now returns a stated error code in all four builds, and the cases that found them are now goldens.

### Fixed (rulings J-0b.1 to J-0b.3, `specifications/stage-j-rulings.md`)

- `vol.garch.forecast` with `horizon` above 100,000 is `E_LIMIT` in every build (Rust and C++ ran past the 20 s limit at 2^31).
- `vol.garch.estimate` on finite returns whose squares overflow binary64 is `E_NON_FINITE` before any search in every build (Python searched for 20 s; Java returned `E_DOMAIN`, C++ `E_NO_CONVERGENCE`).
- Java `exotic.basket.moment` with a ragged `correlation` matrix is `E_INPUT` instead of a crash (exit 70).
