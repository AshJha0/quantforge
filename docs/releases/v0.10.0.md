## What this release is

Plain idea: earlier stages price and risk-manage instruments. Stage H adds the trading side: how to split an order over time, what it costs, how an order book is rebuilt, how orders meet on a venue, and how a paper book records the result, for equities, FX and rates as well as a crypto book. Everything runs on simulated venues except one real input, a crypto exchange's public order book. Nothing is traded.

Formal statement: execution schedules (TWAP, VWAP, POV), Almgren-Chriss trajectory and frontier, square-root and Obizhaeva-Wang impact, implementation-shortfall and pre-trade TCA with attribution, Avellaneda-Stoikov quotes, microstructure estimators and venue analytics, adaptive algorithms, an MBP order-book rebuild, a simulated lit matching engine with auction phases, a simulated dark pool, a smart order router, paper trading on a hash-chained ledger, and equity, FX and rates conventions with simulated venues, in Python, Java, C++ and Rust, each checked against shared goldens.

## The audit

The plan requires a different-model audit of each stage before its tag. A second model (Claude Opus 5.5), with no view of goldens, oracle or tests, read the stage H specs against their sources: 0 Critical, 17 Major and 15 Minor findings. Each was reproduced on the four builds before any ruling (`program/STAGE_H_BLIND_AUDIT.md`), and all 32 are ruled or corrected (`specifications/stage-h-rulings-audit.md`, HR-121 to HR-129). This is a model audit, not a human review: validation stays self-assessment.

## Fixed

Found by the audit and the source check on 2026-11-19, each fixed in all four builds:

- **SEC compliance dates.** The amended tick tier (Rule 612) and fee cap (Rule 610(c)) used the original November 2025 date. SEC order 34-105656 defers both to the first business day of November 2027; round lots have applied since 2025-11-03 (HR-120).
- **Two errors at once.** Almgren-Chriss reported `E_DOMAIN` in Python and Rust and `E_INPUT` in Java and C++ for the same input. One order of checks now, structural `E_INPUT` first (HR-122). POV follows it too.
- **Pair leg B at an exact half** lost a unit when binary64 landed just below the half (0.3 / 0.2 gave 1, now 2; HR-121).
- **`exec.sim.fut.run` had no shared golden**, so cross-language agreement was never checked. It has six now.

Found earlier in the stage:

- VWAP with a subnormal weight returned the wrong slice (1.5 over [5e-324] gave 2.0).
- Router output in Python went through a 28-digit decimal context; the stochastic approximation stopped on flat cost plateaus.
- C++ execution unit tests were never registered with the test runner; a comma in a C++ benchmark test name meant that test never ran.
- Robust curve fit: Java and C++ returned a wrong outlier set with no error, Python and Rust did not converge (ruling D38b).
- The crypto recorder's watchdog killed a healthy recorder.
- One spec golden (`lit_h-0010`) was wrong; the blind lane caught it.

## Evidence

- Outside checks: no free library implements these models, so the check is a blind re-derivation by a second model that sees the rules and inputs and never the first lane's numbers, or a figure printed in the paper (DR-H2). Limit: the blind lane reads the same rules, so it catches arithmetic and convention slips, not a wrong rule. Records: `program/STAGE_H_BLIND_*.md`.
- Sources: every source cited by the multi-asset conventions was read at the issuer's site and is tagged with its URL and date (`specifications/09-microstructure/asset-conventions.md`, HR-119).
- Cross-language agreement: the conformance runner sends every golden to each build; suite `rule_h` adds the first goldens with two errors at once.

## Research results

- **H-1 crypto pilot**: methods run end to end on partial recorded days 2026-11-12 to 11-18. Label: pilot; partial days; crypto venue; not equities or rates; no conclusions. Those days are excluded from any later study (`research/H1-pilot-2026-11.md`).
- **H-18 market making**: an unsigned prereg draft; the strategy ran on simulated data only. No result is claimed.
- **H-9 workload R** (a recorded 6-hour window): correctness passes (0 mismatches in 31,287 book updates per symbol, three languages). **Timing misses the targets**: p99 and p99.9 in every language, and ETH/USD p50 (for example C++ BTC p99 9.2 us against 500 ns, median of 5 runs). The targets were fixed before the run and are unchanged; the miss is recorded as a miss. A recorded update carries about 58 level changes; that per-level figure is descriptive and has no target.

## Honest limits

- Venues, dark pool, router, fills and every equity, FX and rates venue are simulated. Nothing is traded. The only real data is one crypto venue's lit book: crypto, not equities or rates; aggregates only.
- With no `as_of`, the equity tick and fee operations apply the amended (2024) text, which is not in force before 2027-11-01; pass `as_of` for the rule in force on a date. The SEC has those two rules under review, so the date may move again.
- Two convention defaults have no primary source read: USDCAD T+1, and the USD-holiday rule on T+1. The Cboe-style auction tie-break adds an imbalance-side step that is the simulator's own, not Cboe's.
- CME 32nds: quarter-tick price text only; eighth-tick contracts (2-year and 3-year notes) are not supported.
- Latency figures are from one laptop, in-process; no network or venue latency is claimed, and no acceptance-machine run exists. H-5 timings: one local Java run only.
- Rust leaves out the optional `error.field` on some execution errors where the other builds give it; the contract makes that field optional.
- Stage K item K-8 misses its accuracy acceptance and moves to a point release; its threshold is not loosened.
- Validation is self-assessment; there is no second review (owner decision 2026-11-18).
