# v0.9.1 release notes: follow-ups to stage J

Released 2026-11-18 (PRs #50 and #51, and the release PR that bumps the version; tag `v0.9.1`). No new operations; CLI contract unchanged at 1.15.0. Facts below were observed locally (Windows for Python and Java, WSL for C++ and Rust) and in CI on the PRs. The full list is in `CHANGELOG.md` under 0.9.1.

## What this release is

Plain idea: v0.9.0 shipped stage J with a short list of known gaps. This release closes them: hedge solvers that lost accuracy on near-singular problems, faults found by the scheduled fuzz run, a G2++ rate model that returned NaN at extreme mean reversion, and a mutation gate whose verdict depended on luck.

## Fixed

- Near-singular `hedge.qp.solve` with equalities or costs: residual refinement on the solution's face (Java, C++, Rust; Python was already accurate). A 17-case probe suite with exact rational answers goes from 13 misses to 0.
- Fuzz faults J-W3-18 to J-W3-20 (overflowing normal equations, a CIR noncentrality loop, a bound-fill start off the budget) and the CIR tiny-expiry case J-W3-21.
- G2++: C++ returned NaN at `tau = 0` for mean reversion above about 5,500 (0 times an overflowed term), and Python overflowed for very large `a`. Both fixed; C++ and Java now validate G2++ parameters and dates (`E_DOMAIN`) like Rust and Python.

## Changed

- **Mutation gate** (owner decision 2026-11-18). Pull-request samples are seeded from the content of the mutated source, so the same code always gets the same verdict, and samplers leave out proven-equivalent mutants listed in `conformance/mutation/skip-equivalents.json` (signed Equivalent rows only). The 80% target, the 65% Wilson lower bound and the 40-mutant sample are unchanged. Before this, code-touching PRs were red on 9 of 10 runs: at a true kill rate of 85%, the about 12 cells such a PR gates all passed only 17% of the time.
- **Full C++ `hedging.cpp` mutation run** after the fixes (all 947 sites): 843 killed, 100 survived, 4 did not build, 89.4%; with ten new kill tests, 853 of 943 (90.5%). Before the fixes: 701 of 825 (85.0%). Every survivor is classified in `conformance/mutation/hedging-full-run-2026-11-18.md`.
- **No validation status, no second review** (owner decisions 2026-11-18). The curves gallery has no Status column; validation is self-assessment, recorded as such in every golden file's `reviewer` field.
- Maven retries rate-limited downloads (`java25/.mvn/maven.config`).

## Honest limits

- Inputs are synthetic, except the real-data pages (US Treasury curves, SOFR fixings). Nothing is traded.
- New Equivalent mutation rows have no second reviewer, so they stay counted as survivors; the mutation scores above are lower bounds.
- About 100 value-checked cases in older stages have no outside-library check.
