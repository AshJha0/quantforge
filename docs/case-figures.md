# Golden case figures

Generated by `tools/case_figures.py --write`; do not edit. `repo-gates` runs `--check`.

Headline: **8,142 value-checked golden cases**, then 5,936 error cases and 2,554 invariance cases (1,277 pairs: a `same_as` case and its `any` base case, which check that two related inputs get the same answer and no expected number); 16,632 cases of every class in all.

Classes: `ok` is value-checked (numbers within a stated tolerance); `error` checks the error code only; `same_as` checks that a build answers two related inputs the same way (invariance); `any` is the base of such a pair and passes on any finite answer. A build that answers every case with an error code would pass the error cases and none of the value-checked ones, which is why the value-checked count leads.

## Evidence classes per stage

Read from each value-checked case's `verified_by` labels; a case counts once, in the first class below that one of its labels matches. This is a reading of the labels, not rule D6, and the D6 share above is the figure to quote. They differ where a stage records its outside checks in a separate register rather than in the labels (stage F's re-derivation and library registers, stage J's `oracle/OUTSIDE_J.json`, stage K's blind packets), and where a label names a library check of single outputs that D6 does not count (some stage K SciPy cross-checks).

- `impl`: implementation-sourced (expected values are a build's own output)
- `library`: outside library (QuantLib, Strata, ORE, NumPy, SciPy, HiGHS, Python zoneinfo or hashlib)
- `printed`: figure printed in a published source (regulator text, paper, standard test vector)
- `blind`: blind re-derivation by a second AI lane (DR-H2), matched
- `mpmath`: own high-precision oracle (mpmath, 25 to 50 digits)
- `own`: own independent oracle in float64 or exact arithmetic (exact rationals, closed forms, replays, parity, rules)
- `reference`: reference-computed (the spec's reference scheme, stored reference values)
- `hand`: hand-derived only
