# Known issues: open audit findings

This page lists every open Critical or Major finding of the different-model audits of stage K round 1 (three audits, 2026-11-19, by a model that did not write the audited work; plan rule 14.10-5). It is the register that the spec "Limits" sections point to. Since 2026-11-20 it also lists every recorded miss, every move of a plan item to a later point release and the v1.0.0 release-evidence items not yet met ("Recorded misses, moves to a later release and release gaps" below; plan 14.8 K-7). Older known issues are in the [README](../README.md#known-issues). The [results page](results.md) shows these rows beside every stage's test counts, and the [runbooks](runbooks/README.md) say what to do when a daily job, the mutation gate or the release goes wrong.

**State of the code (2026-11-20).** Stage K round 1 and the round 2 fixes are merged to main by 2026-11-20 (pull requests #58 and #59), not tagged; they are released with v1.0.0 (owner decision 2026-11-20: no v0.10.1 tag; the last tag is v0.10.0). The different-model audits A, B, C and the follow-up are answered; what stays open is listed below. Evidence class of every row: measured or read by the auditor, as stated in the audit; rows marked "re-measured" were also checked by the project.

**K-2 at v1.0.0 (owner decision 2026-11-20).** The K-2 gate needs 20 recorded trading days in the daily paper ledger. v1.0.0 does not wait for them, and the threshold is not changed. At the tag, K-2 is stated as "not met: N of 20 recorded trading days", with N counted by the ledger verifier (`tools/paper_daily/verify_ledger.py ... --require-days 20`, full command in `docs/developer-guides/paper-ledger.md`) on the ledger at the tagged commit. N was 0 on 2026-11-20 at 13:00 UTC: the schedule is on main since 2026-11-20 (pull request #59) and no scheduled run had happened yet (read from the workflow run list).

Plain reading: each row says what is wrong in one sentence, with the size where one was measured. "Answered on branch X, merge pending" means a fix exists with tests but is not yet on the integration branch; the row closes when it is merged and its rulings are confirmed.
