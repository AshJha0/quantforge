# Blind lane notes: ambiguities and interpretation chosen

Generated by `blind_ref.py` (plain Python, Decimal arithmetic) from the two spec files and rulings only.

## ob_h (order book)
- Checksum string: asks ascending then bids descending, top 10 each; price and qty formatted at price_decimals / qty_decimals, "." removed, leading zeros stripped, concatenated; crc32 = zlib.crc32 (IEEE). Empty book gives "" and crc32 0 (0010 has no asks; the spec does not say how an empty side is handled, I simply contribute nothing).
- 0001/0010: `crc32` is the final-book checksum whatever input `checksum` is. 0001 expected to equal the venue worked example (3310070434).
- Book strings kept exactly as received; on replace the latest message's string is kept.
- Gap row: clears book, counts `gaps`, emits event kind GAP at its message index (gap rows count in the index), not in `messages`. After a gap, updates are UPDATE_BEFORE_SNAPSHOT (counted in `updates`, 0 level_changes) until a snapshot. `resyncs` stays 0 (spec: only when caller marks a resubscribe).
- Crossed/locked evaluated after every applied message (snapshot or non-ignored update) on current best bid/ask; reported each time the state holds (0006: i=1 LOCKED, i=2 CROSSED). Crossed levels are kept, not removed.
- `truncated_levels` counts levels dropped (0003: 1). Snapshot truncation counted the same way.
- `deletes_of_absent_level` counted per absent price; they also count in `level_changes`.
- Same price twice in one update (0004): last wins (replace), `level_changes` = 2.

## lit_h (lit engine)
- `fees` per trader is a single signed decimal string: taker_fee x notional for taker fills minus maker_rebate x notional for maker fills. Spec does not say whether it is a single number or an object. Zero fee prints "0"; trader appears once it has any fill.
- `cancelled` order is chronological. IOC/MARKET remainders and explicit cancels listed; fully filled IOC has no entry. Modify decreases add to conservation `cancelled` but not to the `cancelled` list (spec lists only explicit cancels, IOC, MARKET).
- UNKNOWN_ID rejects (CANCEL of ZZ in 0011) go in `rejects`; ZZ is not in `conservation` (never submitted).
- MODIFY increase: submitted += (new open qty - current open qty); new seq. Decrease keeps seq.
- Iceberg refresh happens immediately when a slice is filled and hidden remains; new seq taken at that moment (even if the incoming order is then exhausted). Hidden tier is effectively unreachable because the refreshed slice is displayed.
- Level matching order: displayed (LIMIT, iceberg slice, PEG_PRIMARY) by seq, then PEG_MID by seq, then iceberg hidden; price priority before tier, so a PEG_MID at a better price trades first (0008: P1 at 101 trades before B1 at 100).
- PEG_MID: floor/ceil of mid of non-PEG_MID best bid/ask to tick, capped by limit. PEG_PRIMARY: best same-side non-PEG_MID price excluding itself, capped. Repricing after every event, in seq order; a moved peg takes a new seq (0010: P1 moves 100 -> 99 after B1 is consumed, new seq 4, behind B2). Unpriced pegs (no reference) stay resting, untradable, omitted from `book` (not exercised).
- `mbp`: object `{"asks":[[price,qty]...],"bids":[...]}`, levels with displayed qty 0 (hidden-only, e.g. PEG_MID) omitted. `book`: `{"asks":[...],"bids":[...]}` of order records.
- POST_ONLY crossing test and FOK availability count all resting priced orders on the opposite side incl. hidden/peg.
- Conservation `resting` = final open (display + hidden); `filled` totals both taker and maker roles.
- Fill `seq` = fill counter from 1; order `seq` counter separate.
