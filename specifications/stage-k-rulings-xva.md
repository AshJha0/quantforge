# Stage K rulings, item K-8b (xVA extras and AAD xVA sensitivities): PROPOSED

Written 2026-11-19 by the K-8b xVA spec lane (reading and writing only; no code, no runs beyond scratch arithmetic). Status: **PROPOSED** until the coordinator confirms. Numbering starts at KR-160 so it cannot collide with wave 1 (KR-1 to KR-11), wave 2 (KR-50 to KR-69), KR-110 to KR-112 or the margin-model rulings (KR-130 to KR-141). Append-only. Sources: `program/STAGE_K_SOURCES_XVA.md`. Gate: `program/STAGE_K_XVA_GATE.md`.

Why these rulings exist: the sources fix the ideas but leave choices four builds must make the same way (where survival is measured in a bucket, which forward spread a funding curve gives, what a derivative is at a kink, how an MPoR floor is doubled). Each ruling says which way we go and why. Where the outside check is ORE, the ruling follows ORE's written formula ([ORE-X], read) so the comparison is like with like; where that departs from a stage G ruling, the stage G operation is unchanged and the new operation says so.

| KR-161 | AAD derivative and its reference | An AAD output is the derivative of the **computed function** (the discrete sums, the given paths, the chosen quadrature), per unit absolute change of the input, as `aad-core.md`. Reference: the Richardson central difference of `aad-core.md` (`D(h) = (f(x(1+h)) - f(x(1-h)))/(2hx)`, `ref = (4 D(h/2) - D(h))/3`, `h = 1e-4`; an input equal to 0 is bumped by `h` absolutely). Tolerance (plan 14.8 K-8): `|AAD - ref| <= 1e-10 + 1e-8 |ref|` (class `aad_sensitivity`, G-9). Kink rule: a second pair (`5e-5`, `2.5e-5`) must agree with the first within 1e-9 relative, else the bump crossed a kink of `max` (a path's netted value, a funding overlap, an exercise decision) and the case is dropped **before** its golden is frozen, with the reason recorded. At a kink AAD takes the branch the forward pass took (`max(a, b)` takes `a` when `a >= b`), which is a convention, not a derivative; no golden sits on a kink. |
| KR-162 | AAD scope | Differentiated operations: `xva.adjustments.value` (G-41; every scalar and every profile entry), `xva.colva.value`, `xva.funding.asymmetric`, `xva.mva.value`, `xva.wwr.cva_gaussian_copula`, `xva.exposure.closeout_normal`, and the CVA of `xva.exposure.portfolio_hw` with respect to `hazard_rate` and `recovery` (exact one-factor EE held fixed: the EE does not depend on them). Path-based operations are differentiated pathwise with the paths fixed. Operation `xva.sens.aad` takes `{operation, inputs, wrt}` and returns the operation's outputs plus `gradient[output][input path]`. |
| KR-163 | ColVA | ORE form ([ORE-X], read): `COLVA = - sum_(i=0)^(n-1) C_i Delta_i delta_i D(t_(i+1))`, `C_i` the expected collateral balance at `t_i` (positive = received by us), `Delta_i` the spread of the collateral remuneration rate over the discount (overnight) rate on `(t_i, t_(i+1)]`, `delta_i = t_(i+1) - t_i`, `D` the discount factor. Optional `survival`: `NONE` (ORE, default) or `BOTH` (multiply each term by `S_B(t_(i+1)) S_C(t_(i+1))`, the first-to-default discounting of [GK14] eq. COLVA, discretised at the bucket end). Optional `floor` term ([ORE-X] "collateral floor", attributed there to Lichters): `- sum C_i max(-r_i, 0) delta_i D(t_(i+1))` with `r_i` the overnight rate on the bucket, reported separately as `collateral_floor` and never added into `colva`. Sign: received collateral remunerated above the discount rate is a cost, so `colva < 0` for `C > 0`, `Delta > 0`. |
| KR-164 | Asymmetric funding curves | Borrowing and lending spreads are given as zero-spread curves `s_b(T)`, `s_l(T)` (continuously compounded, over the discount curve) at pillars; between pillars linear in `s T` (log-linear in the spread discount factor), flat extrapolation of the forward. Bucket spread `f(t_(i-1), t_i) = (s(t_i) t_i - s(t_(i-1)) t_(i-1)) / delta_i`, the continuously compounded forward spread. Then exactly [ORE-X] FVA: `FCA = sum f_b,i delta_i S_C(t_(i-1)) S_B(t_(i-1)) D_i EE_i`, `FBA = sum f_l,i delta_i S_C(t_(i-1)) S_B(t_(i-1)) D_i |ENE_i|`, `FVA = FCA - FBA`, with EE and ENE the collateralised exposures at the bucket end (G-16). Survival at the bucket start matches G-41. The G-41 overlap rule, when asked, is applied to each forward lending spread: `f_l,i -> max(f_l,i - h_b (1 - R_b), 0)`. Flat curves reproduce G-41 exactly (a property, not an outside check). |
| KR-165 | MVA | ORE form ([ORE-X], read): `MVA = sum_(i=1)^n (f_b,i - s_I) delta_i S_C(t_i) S_B(t_i) D_i E[IM_i]`, survival at the **bucket end** (as ORE writes it; FVA uses the start). `f_b,i` from KR-164, `s_I` the spread earned on posted IM (constant). [GK14] eq. 37 has `(1 - R_B) lambda_B - s_I` in place of `f_b - s_I` and continuous discounting by `r + lambda_B + lambda_C`; with `f_b = (1 - R_B) lambda_B` and the bucket-end discretisation the two agree (stated, inferred). The G-41 `MVA` of `xva.adjustments.value` keeps its own convention and is not changed. Sign: MVA is reported as a positive cost when `f_b > s_I`. |
| KR-166 | Initial margin projection | `xva.im.project` methods: `GIVEN` (caller's expected IM profile); `NORMAL_MPOR` (`IM_i = z_q sigma_i sqrt(mpor_years)`, `sigma_i` the caller's annualised standard deviation of the netted value change, `z_q = Phi^-1(q)`); `REGRESSION` (ORE regression DIM, [ORE-X]: on given paths, `X_p = V_p(t_i + mpor) - V_p(t_i)` (cash flows in the window are the caller's), regress `X^2` on `1, x, ..., x^n` of a given regressor by least squares, `IM_p = z_q sqrt(max(fit_p - mean(X)^2, 0))`; the across-path mean replaces `E_t[X]` as ORE does); `PLACEHOLDER_MODEL` reserved for the project's placeholder initial margin model (KR-160 TODO; `E_INPUT` "not available" until the operation id is set). `q` defaults to 0.99; ORE's fixed 2.33 is not used (we use `Phi^-1(0.99) = 2.3263478740408408`; the ORE comparison sets `dimQuantile` to the same q). |
| KR-167 | Gaussian-copula wrong-way risk | Exposure at bucket end `t_i` is `V_i = mu_i + s_i Z_i` (`s_i > 0`); default time `tau <= t` iff `Y > Phi^-1(1 - PD(t))`, `PD(t) = 1 - exp(-h t)`; `corr(Z_i, Y) = rho` for every `i`, `|rho| < 1`; **`rho > 0` is wrong way** (high exposure with early default). `CVA = (1 - R) sum_i D_i E[V_i^+ 1{t_(i-1) < tau <= t_i}]` (G-16 bucket convention). Closed form in the spec through the bivariate normal CDF; builds compute `Phi_2` to 1e-14 absolute (Drezner-Wesolowsky with Genz's refinement, or adaptive quadrature); `rho = 0` gives the independent bucket CVA exactly. The wrong-way factor is reported per bucket: `E[V^+ 1{bucket}] / (EE_i (PD(t_i) - PD(t_(i-1))))`. This is a project construction (inferred from [MV19], read); it is not the G-44 Hull-White hazard model and not ORE's dynamic-credit model, so ORE gives no check of it (survey). |
| KR-168 | Stressed exposure | `xva.exposure.stressed_eepe` takes, per netting set, two undiscounted EE profiles on one grid starting at `t_0` (current calibration and stress calibration), and a capital weight `w_ns` (capital per unit EAD; caller's, from the credit framework, not implemented). Effective EE and Effective EPE as G-40 over the first year, or until the last maturity if all trades mature within a year (CRE53.12-53.13, read). `EAD = alpha x EEPE`, `alpha` default 1.4 (CRE53.14); a caller alpha in `[1.2, inf)` only with `own_alpha: true` (CRE53.16), else `E_DOMAIN`. The choice of calibration is **portfolio level** (CRE53.7): the one with the greater `sum_ns w_ns EAD_ns` applies to every netting set; ties take current. The stressed calibration itself (which window, which parameters) is the caller's and is not built here. Label: "regulatory formula on caller inputs; not a regulatory return". |
| KR-169 | MPoR supervisory floor | `xva.mpor.days` (CRE53.24-53.26, read): `F = 5` business days for netting sets of repo-style transactions only, else 10; `F = 20` if trades exceeded 5,000 in the previous quarter or the set holds illiquid collateral or a hard-to-replace OTC derivative; if more than two margin-call disputes lasting longer than the MPoR occurred in the previous two quarters, `F -> 2F` ("at least double the supervisory floor"); then `MPoR = F + N - 1` for re-margining every `N` business days (CRE53.26). Order: base floor, 20-day override, doubling, `+ N - 1`. Output is the floor; a caller's longer MPoR is allowed and reported as `binding: false`. |
| KR-170 | Close-out exposure with VM and IM | `xva.exposure.closeout` extends G-40 on given paths: `E_p(t_i) = max(V_p(t_i) - VM_p(t_i - l) - IM_p(t_i - l), 0)`, where `VM` follows G-40 (threshold, MTA, IA) and `IM` is initial margin **received** (segregated, not rehypothecated, so it never offsets negative exposure; IM posted by us enters ENE only through the caller's `im_posted` profile). `l` in grid steps. The value at `t_i` is the close-out value as given: cash flows inside the MPoR window are the caller's (ORE's `mporCashFlowMode` has no counterpart; the ORE route uses dates with no cash flow in the window). `xva.exposure.closeout_normal`: the one-factor closed form, `V(t) = v_0 + s Z`, `s = sigma sqrt(mpor_years)`, collateral held `VM = max(v_0 - H, 0)` (receive threshold `H`) and IM given: `EE = m Phi(m/s) + s phi(m/s)`, `m = v_0 - VM - IM`. |
| KR-171 | LSMC | `pricing.american.lsmc` follows [LS01] exactly: backward induction over exercise dates; regression only on in-the-money paths; the regressand is the **realised** discounted cash flow of the current stopping rule (never the fitted value); exercise when immediate exercise is strictly greater than the fitted continuation (tie: continue); basis `MONOMIAL` of order n (1, x, ..., x^n) or `LAGUERRE` (the weighted Laguerre functions of [LS01] eqs. 2-4 on `x / x_scale`, `x_scale` the strike, as a stated choice); least squares by QR (a singular design, fewer ITM paths than basis functions, keeps the date with no exercise). Optional separate pricing paths (two-pass, `training_seed`, `pricing_seed`), reported. Paths from the project's portable generator as `mc-greeks.md`, antithetic pairs on request. `xva.exposure.amc` regresses each path's value at exposure dates on the same basis and returns EE, ENE from the fitted values (AMC exposure). | KR-296 | One survival point for FVA and MVA (**CONFIRMED 2026-11-21**, coordinator) | **Plain idea.** FCA, FBA and MVA all charge a funding spread on an amount held over a bucket `(t_(i-1), t_i]`; the charge is paid only while both names are alive. Version 0.1.0 of the specs weighted FVA by survival at the bucket start and MVA at the bucket end. **Ruling.** Both take `S_C(t_(i-1)) S_B(t_(i-1))`, the start. KR-165's MVA formula becomes `sum_i (f_b,i - s_I) delta_i S_C(t_(i-1)) S_B(t_(i-1)) D_i IM_i`. **Evidence.** (1) read, 2026-11-20: ORE's own code computes FCA, FBA and MVA increments with survival at `d0`, the bucket start (`OREAnalytics/orea/aggregation/staticcreditxvacalculator.cpp`, `calculateNettingSetFcaIncrement`, `calculateNettingSetFbaIncrement`, `calculateNettingSetMvaIncrement`, at tag v1.8.16.0 and on master commit 3d75a69087, fetched with the GitHub API); the bucket-end `S(t_i)` appears only in ORE's documented MVA formula (`Docs/UserGuide/methods/xva.tex`, eq. MVA, read), so the cited source disagrees with itself and its code is what the O route (mva_k-0006, 0007) would compare against: a bucket-end golden would sit about `1 - exp(-(h_C + h_B) delta)` (3% on an annual grid) away from ORE, far outside `3 SE`. (2) read (repo): the released G-41 `xva.adjustments.value` computes FCA, FBA, MVA and KVA with the joint survival at the bucket start (`oracle/python/gen_stage_g_w4b.py`, `adjustments`, "first-to-default: both alive at the start of the bucket"), so the start keeps K-8b consistent with what is already released. (3) read: [GK14] eq. 37 is a continuous integral; any left- or right-point sum converges to it as `delta -> 0` (inferred), so the source does not choose a discretisation.
