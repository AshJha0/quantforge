# Stage K rulings, stage G margin replacement (v0.10.1): KR-150 to KR-155

Written 2026-11-19 by the stage G margin-model fix lane (branch `k-margin`), before any value, golden or code change; the change itself follows in later commits on the same branch. Status: lane ruling, for the coordinator to confirm. Numbering starts at KR-150 so it cannot collide with the other stage K lanes (KR-1 to KR-141 are used on this and other branches). Append-only.

Why these rulings exist (plain idea): the stage G operation `xva.simm.ir_delta` takes its weights and correlations as inputs (G-43), so the code holds no number; but the numbers written into its goldens, the tutorial, the question bank and two unit tests were typed by hand in commit `ca78abb2` with the comment "illustrative, regular-volatility-style magnitudes", and no ruling or spec says they were invented by a rule (`program/STAGE_K_ISDA_AUDIT.md`, finding (c), evidence class: read). The project uses no ISDA material (owner decision 2026-11-19). The owner decided on 2026-11-19 to replace those values and rename the operation in this round. This lane did not open, fetch, search for or quote any ISDA document or parameter set, did not open the Open Source Risk Engine's margin calibration files, and compared no value with any outside parameter set.

| # | Point | Ruling |

| KR-150 | Stage G margin table: rule | Every value that the audit classed "origin not documented" is replaced by a value from a stated, visibly artificial rule, the same rule as the K-8h placeholder table (KR-130, `tools/gen_sbim_placeholder.py`). Tenor grid of the stage G cases: 0.25, 1, 2, 5, 10 and 30 years with index `k = 1..6` (labels only: after this ruling no number depends on the tenor lengths). Risk weight `RW_k = 10 x k` (10, 20, 30, 40, 50, 60). Tenor correlation `rho(k, l) = 1 - 0.1 abs(k - l)` (0.9, 0.8, 0.7, 0.6, 0.5); this replaces both the weight vector `[109, 105, 90, 71, 66, 66]` and the formula `exp(-0.3 abs(ln(T_k / T_l)))` with its 0.3 constant. The matrix is positive semidefinite: `max(0, 1 - abs(x) / 10)` is a triangular kernel whose Fourier transform is a squared sinc, so it is positive definite on the line (inferred), and the smallest eigenvalue of the 6 by 6 matrix is 0.0536 (measured, numpy, 2026-11-19). Values that the audit classed as documented constructed test values stay: the concentration thresholds `1e9`, `1e6` and `0` (error case), the hedge case's weights `[100, 100, 0, 0, 0, 0]` with all-ones correlations, and the unit tests' `4e6`, weight 1, threshold `1e6`. |
| KR-151 | Stage G margin table: single source | `tools/gen_sbim_placeholder.py` writes a second file, `specifications/tables/stage_k/sbim-ir-delta-g.json` (header `placeholder: true`, label "placeholder weights"), and `--check` covers both files; `tools/test_sbim_placeholder.py` recomputes every number of the new file from the rule, rejects a planted change, and fails if the old weight vector or the old correlation constant appears in any tracked file outside the history files it names. Consumers read the file, never a copy: the golden generator `oracle/python/gen_stage_g_w4b.py`, tutorial 15's example. A unit test in a language build that needs one weight uses a value that follows the rule and says which entry it is (for example 30, the 2Y entry, `10 x 3`); no hand-typed margin parameter remains. |
| KR-152 | Operation rename and deprecated alias | The operation is renamed `xva.sbim.ir_delta` ("sbim": sensitivity-based initial margin, the generic name of K-8h, KR-130). The old id `xva.simm.ir_delta` stays for one release as a **deprecated alias**: every build dispatches it to the same function as the new id, so outputs, error codes and diagnostics are identical. How deprecation is signalled: the contract has never deprecated anything before (searched 2026-11-19: no "deprecat" or "alias" in `specifications/` at `527dbebe`; R6-5.1 renamed outputs in place with no alias), and its output schema does not allow extra fields ("Extra keys in `outputs` are a failure; missing keys are a failure", `specifications/cli-contract.md`, section "Result document"). So the minimal mechanism is: no output change; the deprecation is stated in the contract text (a new section "Deprecated aliases") and in one machine-readable list, `specifications/deprecated-aliases.json` (alias, target, contract version that deprecated it, removal release), which `tools/gen_name_map.py` reads so that the alias's name-map row carries `deprecated_alias_of` and the target's library names. Removal is scheduled for `v1.0.0`. |
| KR-153 | Library names, goldens and the name map | Library functions renamed to the F-5 shape of the new id: Rust and Python `sbim_ir_delta` (module `xva`), Java `Xva.sbimIrDelta`, C++ `qf::xva::sbim_ir_delta` (new header `cpp26/include/quantforge/core/xva.hpp`; before this ruling the C++ build computed inside the CLI handler `op_xva_simm` and the name map's `qf::xva::simm_ir_delta` did not exist, and the Java method was `Xva.simm` while the name map said `Xva.simmIrDelta`: both mismatches are fixed by this rename). The library functions keep no old-name alias (the contract alias is the compatibility promise). Golden suite `stage_g/simm_g.json` becomes `stage_g/sbim_g.json` (case ids `sbim_g-0001` to `-0008`, tag `sbim`), regenerated once through the oracle with the KR-150 table. A small alias suite `stage_k/sbim_alias_k.json`, written by the same generator, holds for each `sbim_g` input an invariance pair (the new id with expected `any`, the alias with `same_as` that case), one E1 case per Real input of the alias (F-2, `E_DOMAIN`) and one case with two errors at once (HR-66). Every downstream golden that copies the old values or names (`stage_g_e1/e1g_xva.json`, `stage_j/fuzzfix_j.json`, `cpp26/tests/cli_cases.inc`) is regenerated by its own generator. |
| KR-154 | Contract version | The rule (`specifications/cli-contract.md`, section "Versioning"): "Adding an operation or an error code is a minor version. Changing the meaning of a key, a code or an exit status is a major version." Adding `xva.sbim.ir_delta` is adding an operation: minor. The alias keeps every key, code and exit status with its meaning: not major. The changed golden values are not a change of meaning: the formula is unchanged and the same inputs give the same outputs; what changed are the inputs written into the goldens (G-43: weights and correlations are inputs). So the change is minor. KR-1 (owner decision K-QC) gives one contract number, 1.17.0, to every stage K wave, and 1.17.0 has not been released (`v0.10.0` reported 1.16.0), so this change ships inside 1.17.0 and no new number is needed. The rule does not name the removal of an operation; this ruling counts removing an operation id as a major change (callers that use it break), so the alias's removal is tied to the `v1.0.0` release and its major contract step (inferred). |
| KR-155 | Outside checks and wording | Outside-checked status: at `527dbebe` the register counts 4 value cases of `xva.simm.ir_delta`, 0 outside-checked (`oracle/OUTSIDE_SHARES.md`; the generator says "No outside library: not counted"), so no case loses outside-checked status and stage G's share changes only by the renamed row; the alias suite adds no value-checked case (invariance and error cases leave the denominator, `tools/outside_shares.py`). Wording: every "SIMM" in code comments, docs, tutorials, question bank, model inventory, limits and current release notes becomes the generic name ("sensitivity-based initial margin", "sbim"), except the one public section that explains why there is no ISDA SIMM here (`docs/model-inventory.md`), the alias's contract entry, and history records under `program/` (handovers, audits, blind packets), which are not rewritten; older `CHANGELOG` entries are reworded to the generic name with a note that the release shipped the old id; the old operation id may still be named where it refers to the alias or to what a released version shipped. |
