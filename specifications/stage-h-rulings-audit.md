# Stage H rulings from the different-model audit (HR-121 to HR-129)

Written 2026-11-19 by the stage H coordinator under the owner's delegation. The audit (plan rule 14.10-5; Claude Opus 5.5, read-only, no view of goldens, oracle or tests) reported no Critical finding, 17 Major (HA-1 to HA-17) and 15 Minor (HA-18 to HA-32). Each finding was first reproduced by sending probe cases to the four builds. Where the four builds already agreed, the ruling states that behaviour and a golden pins it. Where they disagreed, or a build broke the stated rule, the code changed in all four builds. Goldens: suite `rule_h` (`oracle/python/gen_stage_h_audit.py`), 11 value cases and 29 error cases. Normative on merge; append-only.

## What the probes found

- **Two real faults.** (1) The four builds disagreed on the Almgren-Chriss error code when two errors applied at once: Python and Rust reported `E_DOMAIN` (sigma < 0) where Java and C++ reported `E_INPUT` (N < 1). No golden had two errors, so conformance never saw it (HR-122). (2) The pair leg B rounding lost a unit at an exact half that binary64 lands just below (0.3 / 0.2), in all four builds alike (HR-121).
- **One rule broken in all four builds alike.** POV checked `participation` (a domain error) before an empty `market_volume` (a structural error), against HR-66 (HR-122).
- **Everything else: the builds already agreed.** POV and the close already snap before flooring; `sigma = 0` already returns the linear trajectory; the arrival schedule already avoids the sinh overflow; every unstated domain already had the same code in the four builds. Those findings were gaps in the text, closed below.

## Rulings

| # | Audit finding | Ruling |
|---|---|---|
| HR-121 | HA-3, HA-31 | **Whole-unit rounding of a binary64 value.** Inputs are binary64 numbers, so "exact" arithmetic on the decimals a user typed is not available at this interface. Rule: a value within 1e-12 relative of an integer is that integer before a floor (POV child `p v / (1 - p)`, close cap `p_c V_c`), and `x + 1/2` within 1e-12 relative of an integer is that integer before the floor of a half-up rounding (pair and basket leg quantities). So `0.03 x 97 / 0.97` gives 3 and `0.3 / 0.2` at C = 1 gives 2. POV and the close already did this in the four builds; the pair did not and is fixed in all four. The POV property "realised participation equals p wherever not capped" holds in CONTINUOUS mode only |
| HR-122 | HA-1, HA-2, HA-27 | **One order of checks for the stage H operations**, replacing the two orders in HR-66 and in `cli-contract.md`: (1) `E_SCHEMA` (shape, type, an unlisted enum spelling, a non-finite decimal string per HR-12); (2) `E_LIMIT` for a size limit on the input itself (HR-9 bucket and step counts, HR-17, HR-116 integer ranges); (3) the F-2 finite rule: a non-finite Real is `E_DOMAIN`; (4) structural `E_INPUT` (an empty or missing list, a count below 1, lengths, ordering, a non-positive or fractional order quantity where HR-56 says so, cross-field consistency); (5) `E_DOMAIN` (one value outside its domain); (6) `E_LIMIT` for a limit that only arises after validation (the HR-58 router grid). This is what the four builds do and what `cli-contract.md` "Error precedence" says; HR-66's "`E_LIMIT` last" is narrowed to step (6). An unlisted enum value is `E_SCHEMA` everywhere; HR-66's "enum or mode consistency" means cross-field consistency only. Exception recorded: `paper.pretrade.check` reports an unknown `side` or `type` as `E_INPUT` and checks a missing `limit_price` after the quantity domain (`paper-trading.md`, "Errors"; pinned by `pt_h`); it is left as it is. A non-positive quantity is `E_INPUT` for orders (schedules, algos, pre-trade) and `E_DOMAIN` for venue events (lit, dark, router, paper): the split is deliberate. Code changes, four builds: POV reports an empty `market_volume` before `participation`; Almgren-Chriss reports N < 1, X <= 0 and an empty `risk_aversions` before T, sigma, epsilon, gamma and `eta_tilde`. The order binds the command-line operations and the library functions that take raw inputs. A typed parameter object that checks itself when built (Java `AcParams`, ADR-0011 rule 4) reports its own errors at construction, before any list is seen; Java therefore has a raw-input `acFrontier` that the CLI uses |
| HR-123 | HA-7, HA-11 | **Codes for stated domains.** A value outside a stated domain is `E_DOMAIN`: AS `sigma < 0`, `time_left < 0`, `risk_aversion <= 0`, `k <= 0`; AC `risk_aversion < 0`; a negative VWAP weight; an all-zero VWAP profile; a negative market volume. Structural `E_INPUT`: an empty `risk_aversions`, an empty profile, `n_buckets < 1`, a fractional quantity in UNITS mode. A currency outside the eight ranked ones of HR-88 is `E_INPUT` in `micro.fx.pip_value` and `micro.fx.spot_date` (no default order or settlement lag is invented for it) |
| HR-124 | HA-5, HA-23, HA-29 | **Almgren-Chriss at y = 0.** When `y = lambda sigma^2 tau^2 / (2 eta_tilde)` is 0 (lambda = 0, sigma = 0, or the product underflows), the output is the linear trajectory with `kappa = 0`. `x_0 = X` and `x_N = 0` are assigned, not computed. Naming: `acosh(1 + y) / tau` is kappa, the root of the cosh equation; [AC00]'s kappa-tilde is `sqrt(lambda sigma^2 / eta_tilde)` |
| HR-125 | HA-6 | **Arrival schedule for large kappa N.** The ratio `sinh(kappa (N - j)) / sinh(kappa N)` is evaluated in the exponential form of HR-6, so it never overflows; at kappa N = 800 the first slice is X to rounding |
| HR-126 | HA-7 | **Shortfall with no fills.** `vwap_slippage` is the sum `sum q_i (p_i - benchmark_vwap)`, so with no fills it is 0, as are `delay` and `execution`; the whole order is opportunity cost |
| HR-127 | HA-9 | **Auction with no cross.** If the largest matched volume over the candidates is 0 (one side empty, or both present and not crossing), there is no auction: `price` null, `volume` 0, `imbalance` 0, no fills, every order residual (HR-101 extended). A limit off the `tick_size` grid is `E_DOMAIN` |
| HR-128 | HA-12, HA-32 | **Lit engine quantities.** A `qty`, `display_qty` or MODIFY quantity that is not a positive multiple of `lot_size` is `E_DOMAIN`, as a price off the tick grid is; MODIFY to 0 is `E_DOMAIN`. MODIFY of an id that is not open is the reject `UNKNOWN_ID` and changes nothing. MODIFY sets the total open quantity |
| HR-129 | HA-13, HA-14, HA-8 | **Dark pool, order book, router wording.** Dark `min_qty` defaults to one lot (`lot_size`), in the pool model and the harness alike; `min_qty` above `qty`, or a quantity off the lot grid, is `E_DOMAIN`. Order-book resync: a snapshot counts as a resync when the message carries `"resubscribe": true` and a checksum failure is pending, as the four builds implement; HR-15 is read with that condition. Router `SAMPLE_AVERAGE`: the search is exhaustive over the integer grid 0..S per coordinate, ties to the lexicographically smallest tuple, when the grid has at most 10^6 points; above that it is exact coordinate descent from the [CK] start, which is a local method and is labelled so; `ranking` on a larger grid is `E_LIMIT`. The other two wordings are withdrawn |

## Findings closed by other rulings or by text

- HA-4 (pre-trade duration): `adv` is the average daily volume **including** the order's own volume, so `T = X / (p adv)` stands and no golden changes. Stated in `tca-pretrade.md`. With a historical ADV that excludes the order, use `X (1 - p) / (p adv)`; that variant is not implemented.
- HA-10 (FX seed range), HA-15 (multi-asset rulings were still marked draft), HA-16 (unverified sources), HA-17 (workload R window), HA-19 (32nds digit): fixed earlier on 2026-11-19 (HR-116 text, HR-118, HR-119, `low-latency-targets.md`).
- HA-18 (round lot): `price` in `micro.eq.round_lot` stands for the Evaluation-Period average closing price of Rule 600(b)(93); the six-month operative period is not modelled. Stated in `asset-conventions.md`.
- HA-20 (random last-look rejects): `LL_RANDOM` is a stand-in for validity and credit rejects; it is not taken from the FX Global Code (HR-119).
- HA-21 (HR-70 gate probability): the 2.4e-4 figure holds for the normal-approximation estimators only. For the OLS tests the miss probability per seed is higher (t with 19 or 29 degrees of freedom): the audit computes a gate failure probability of up to 0.017 for resilience. The gate and its threshold are unchanged; the stated figure is corrected in `stage-h-rulings-micro.md`.
- HA-22 (stale derivation text for eqc_h-0007), HA-24 ([CK] "Definition 1, eq. (5)"), HA-25 ([TLD11] read; the 1/h scaling is from [AFTHL05]), HA-26 (paper trading rulings confirmed), HA-28 (pinning and repeats in the R result), HA-30 (T+1 is the first business day of the non-USD currencies after the trade date): text corrections in the files named.
