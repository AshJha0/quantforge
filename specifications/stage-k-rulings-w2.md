# Stage K rulings, wave 2 regulatory capital (K-8a, K-8f, K-8g, K-8i): PROPOSED

Written 2026-11-19 by the stage K wave 2 spec lane (reading and writing only; no code, no runs). Status: **PROPOSED** until the coordinator confirms. Numbering starts at KR-50 so it cannot collide with wave 1 (KR-1 to KR-11 on `k-spec`). Append-only. Source of record for every number: the Basel Framework PDF generated 11/11/2026, read 2026-11-19 (`program/STAGE_K_SOURCES_W2.md`); parameter tables in `specifications/tables/stage_k/`.

Why these rulings exist: the Basel text leaves choices open that four language builds must make the same way (sign conventions, tie rules, boundary equality, what happens under a square root that goes negative), and in two places the formula image and the paragraph text differ. Each ruling says which way we go and why; none changes a published number.

|---|---|---|
| KR-50 | Text of record | The 11/11/2026 consolidated PDF is the source for wave 2 (evidence class read). Paragraph numbers and PDF pages are cited as `MAR22.24 (p. 627)`. Formulas come from the embedded images; where an image and the paragraph text differ, the text wins and the difference is recorded (KR-58). The parameter tables in `specifications/tables/stage_k/*.json` are the single copy all four builds read or generate from; a build that hard-codes a parameter must have a test comparing it with the table. |
| KR-51 | DRC inputs and signs | `risk.frtb.drc_nonsec` takes per position: `id`, `obligor`, `bucket` (`CORPORATE`, `SOVEREIGN`, `LOCAL_GOV`), `seniority` (`COVERED`, `SENIOR`, `NON_SENIOR`, `EQUITY`), `notional` (signed: long positive, short negative, MAR22.13), `market_value` (the bond-equivalent market value of MAR22.14 Table 1, signed like notional), `maturity_years`, optional `lgd_applies` (default true; false is MAR22.12(4)). P&L = `market_value - notional` (MAR22.11(2)). For equity, notional is the market value, so P&L is 0 and JTD = market value (no face value exists; MAR22.16 FAQ example treats a EUR 10m equity position as JTD 10m). The Table 1 mapping from CDS and options to (notional, bond-equivalent market value) is the caller's; the spec shows it in a worked example. Ratings are per obligor (`ratings` map); an obligor with no rating entry is `E_INPUT`. |
| KR-52 | Maturity weight | Weight `w = 1` if `maturity_years >= 1`, else `max(maturity_years, 0.25)` (MAR22.15, MAR22.18), applied to gross JTD before offsetting (footnote 296). For positions flagged `cash_equity: true` (stocks, MAR22.16) `maturity_years` must be 0.25 or at least 1 (MAR22.16 and its FAQ); any other value is `E_DOMAIN`. Equity derivatives use the contract maturity (MAR22.17) and are not restricted. `maturity_years <= 0` is `E_DOMAIN`. |
| KR-53 | Offsetting within an obligor | Seniority ranks: `COVERED` 4, `SENIOR` 3, `NON_SENIOR` 2, `EQUITY` 1. A short may offset a long of equal or higher rank (MAR22.19(1)). Deterministic greedy rule: take shorts in descending rank (ties: input order); each consumes eligible longs in ascending rank (ties: input order) until it is used up. A short of rank r may use the longs of rank r or above, so the eligible sets are nested (a junior short's set contains a senior short's set); serving the most restricted shorts first therefore offsets the largest total possible, and since one obligor has one rating (KR-51) the net amounts do not depend on which eligible long was used. Unmatched longs sum to the obligor's net long, unmatched shorts to its net short; an obligor can have both (MAR22.21). Ruling on `COVERED`: MAR22 gives covered bonds an LGD, not a seniority; we rank them as the most senior debt. |
| KR-54 | Empty sums | If a bucket has no net long and no net short, HBR is not defined (0/0); the bucket is reported with `hbr: null` and `drc: 0`. A bucket with only shorts has HBR 0 and DRC 0 (floor). |
| KR-55 | Securitisation risk weights | MAR22.34 and MAR22.42 take securitisation risk weights from the banking book framework CRE40-CRE44, which this lane did not read and the library does not implement. `risk.frtb.drc_sec_nonctp` and `risk.frtb.drc_ctp` therefore take a caller-supplied `rw` per position and implement only the netting, HBR and aggregation algebra (MAR22.29-22.33, MAR22.39-22.45). Output label: "securitisation risk weights supplied by the caller (CRE40-CRE44 not implemented)". `risk.frtb.drc_ctp` also accepts `bucket_drc` (a list of index-level DRC_b) instead of positions, so the MAR22.45 printed example can be run as written. |
| KR-56 | PLA statistics | Inputs `hpl` and `rtpl`, equal length n >= 3 (unequal: `E_INPUT`; MAR32.35 asks for 250). Ranks with ties get the average rank (MAR32.36 does not say; average ranks keep r_S symmetric and equal SciPy's default). Spearman per MAR32.38 on the ranks (Pearson correlation of ranks, population covariance and standard deviations; the n or n-1 factor cancels). A constant series has zero rank variance: `E_DOMAIN`. KS: ECDF step 1/n (0.004 at n = 250, MAR32.39-32.40), D = max over all pooled values of the absolute ECDF difference (MAR32.41), computed in integers as `d = max |count_rtpl(x) - count_hpl(x)|`, `ks = d / n`. Zone tests are made on exact rationals: green iff `r_S > 0.80` and `100 d < 9 n`; red iff `r_S < 0.70` or `100 d > 12 n`; else amber. Equality at a threshold is therefore amber (the text uses strict "above" and "below" for both green and red). `r_S` is binary64; a value within 1e-12 of 0.80 or 0.70 is compared as computed and the golden avoids such values except the stated boundary cases. Output also `ks_pvalue_asymptotic = Q_KS(D sqrt(n/2))`, the Kolmogorov tail, which reproduces the printed p-values of MAR32.42 (0.2634 against printed 0.264; 0.0546 against printed 0.055). `regulatory_window: true` only when n = 250. |
| KR-57 | ES inputs | `risk.frtb.ima.es_lh` takes either `es_t` (five numbers ES_T(P,j), j = 1..5, j = 1 being ES_T(P)) or `pnl` (five lists of 10-day P&L scenarios, list j for shocks to Q(p,j)), each list then reduced to ES at 97.5% with the existing `risk.var.historical` estimator (`06-risk/var-es-and-backtests.md`, losses positive). A negative ES_T value is `E_DOMAIN` (the capital formula squares it and would hide a sign error). Missing horizons are 0 (no risk factor with that LH). Parametric mode `sigma` (five standard deviations of 10-day P&L) uses the normal ES `sigma phi(z)/(1 - 0.975)` with `z = Phi^-1(0.975)`, factor 2.337802792201415. |
| KR-58 | Ratio floor | MAR33.6(2) text floors `ES_F,C / ES_R,C` at 1; the image on p. 672 and the IMCC image on p. 676 omit it. We apply the floor to the portfolio ratio and to each risk-class ratio in IMCC(C_i), and report `ratio_floored: true` when it binds. `ES_R,C <= 0` is `E_DOMAIN`. |
| KR-59 | RFET counting | Inputs: `as_of` date, list of observation dates (ISO dates; duplicates allowed). Count distinct calendar days only (MAR31.13). The 12-month window is (as_of minus 12 calendar months, as_of], end-of-month clamped. Criterion 1: at least 24 distinct days in the window **and** every window of 90 consecutive calendar days lying wholly inside the 12 months has at least 4. Criterion 2: at least 100 distinct days in the window. Pass = 1 or 2. Simplification stated: the "period used to calibrate the current ES model" of criterion 1 is taken as the same 12 months (footnote 301 allows the RFET period to differ by up to one month; we do not model a lag). Bucket assignment `risk.frtb.rfet.bucket`: row A, B, C or D of MAR31.16 Table 1, lower bound inclusive, upper exclusive; D accepts 0 <= delta < 1; delta = 1 is `E_DOMAIN` (the printed last bucket is 0.95 <= delta < 1.00). |
| KR-60 | Liquidity horizon assignment | `risk.frtb.ima.lh` maps a category of MAR33.12 Table 2 to n; optional `maturity_days` applies FAQ4 (if maturity < n, the smallest of 10, 20, 40, 60, 120 that is at least the maturity); optional `constituents` (weight, n) applies FAQ5 (smallest of the five at or above the weighted average; weights must sum to 1 within 1e-12, else `E_DOMAIN`). An FX pair is "specified" if listed in footnote 309 in either order, or if it is a first-order cross of two listed pairs (both currencies appear in listed pairs sharing a common third currency). |
| KR-61 | IMA capital | `risk.frtb.ima.capital`: `m_c = MAR32.9 Table 1 multiplier(exceptions) + qualitative_addon` (default 0); `C_A`, `IMA_G,A`, `k`, surcharge and `ACR_total` exactly as the images of MAR33.41, 33.43, 33.45. No amber desk: `k = 0`. `sum SA_i` over green and amber desks equal to 0 with an amber desk present is `E_DOMAIN`. Exceptions is an integer >= 0; 10 or more gives 2.00. |
| KR-62 | SA-CVA roots | MAR50.53 writes no floor under either square root. With the printed correlation tables a negative radicand is possible in principle (the matrices are not checked here to be positive semi-definite). We floor each radicand at 0, as MAR21.4(4) does for the market risk version, and report `floored: [bucket ids]`. This is a ruling, not text. `S_b` is always the clipped sum (MAR50.53(3)); there is no unclipped first attempt and there are no high/low correlation scenarios (MAR50 does not refer to MAR21.6). |
| KR-63 | SA-CVA inputs | Per risk class: list of `{bucket, factor, s_cva, s_hdg}` net sensitivities already in the MAR50 units (change in CVA or hedge value divided by 0.0001 or 0.01 as MAR50.56-50.77 define). The caller computes the sensitivities (an exposure model is out of scope for K-8g; the xVA lane K-8b may later feed them). Counterparty credit spread factors carry `name`, `tenor`, `quality` (`IG` or `HY_NR`), `legal_group` and, for bucket 8, `index` and `series`, so that rho = rho_tenor x rho_name x rho_quality can be computed (MAR50.65(4)-(5)). `m_cva` defaults to 1 (MAR50.41). |
| KR-64 | BA-CVA inputs | Per counterparty: `sector`, `quality` (IG or HY_NR), netting sets `{ead, m, imm}`; `imm: true` gives DF = 1 (MAR50.15(4)); `m` has no five-year cap (MAR50.15(2)); `m <= 0` is `E_DOMAIN`. DF is computed as `-expm1(-0.05 m) / (0.05 m)` to avoid cancellation for small m (same value as the printed formula; differs from the naive form by up to about 2e-15 relative at m = 0.1). Hedges for the full version: single-name `{counterparty, relation (DIRECT, LEGAL, SECTOR_REGION), sector, quality, m, notional}`, index `{m, notional, constituents: [{sector, quality, weight}]}`, index RW = 0.7 x name-weighted average of the MAR50.16 weights (MAR50.24(4)). |
| KR-65 | Leverage ratio scope | `risk.capital.leverage` is a simplified LEV30: on-balance sheet values (caller: accounting value less specific provisions), derivative netting sets `{v, cvm_received, cvm_provided, pfe}` with `pfe` supplied by the caller or taken from `risk.ccr.sa_ccr` (K-8d) with the multiplier forced to 1, written credit derivatives `{notional, fv_reduction_in_tier1, purchased_offset}`, SFTs `{gross_assets, exposures E_i, collateral C_i, mna}`, off-balance sheet `{notional, ccf_category}`. Left out: CCP client clearing (LEV30.26-30.29), cash pooling (LEV30.12), trade-date unsettled offsets (LEV30.10-30.11), securitisation derecognition (LEV30.5), central bank reserves exemption (LEV30.7), agent SFTs (LEV30.41-30.44), the purchased-protection eligibility tests of LEV30.31(1)-(5) (the caller asserts eligibility), deductions of LEV30.3, Tier 1 itself (input), the G-SIB buffer (LEV40). Output label: "simplified leverage ratio (LEV30 subset); not a regulatory return". |
| KR-66 | Large exposures scope | `risk.capital.large_exposures` takes Tier 1, a group map (connectedness of LEX10.9-10.18 is the caller's judgement), banking book exposure values (LEX30.3-30.6 applied by the caller except the 10% CCF floor, which the operation applies to given `{notional, ccf}`), CRM substitution `{protected, provider}` (LEX30.13-30.14), and trading book positions as in KR-51 with LGD forced to 100% and no maturity weight (LEX30.17-30.18), offset by LEX30.22-30.23 using the KR-53 rule. Large iff exposure >= 10% of Tier 1; breach iff > 25% (or > 15% when both sides are flagged G-SIB). Left out: exemptions other than a caller `exempt` flag (LEX30.31-30.59), look-through for funds and securitisations (LEX30.41-30.53), covered bonds (LEX30.37-30.40), the LEX30.28 non-financial CDS rule, interbank and CCP treatments. Output label: "simplified large exposures (LEX subset); not a regulatory return". |
| KR-67 | Numbers and errors | Real inputs and outputs are JSON numbers (binary64); the F-2 finite rule applies (non-finite is `E_DOMAIN`). Goldens compare to 1e-12 relative (1e-15 absolute at 0), except cases tied to printed rounded figures, whose tolerance is stated per case before any run. Error order as HR-122: `E_SCHEMA`, `E_LIMIT` for input size (at most 100,000 positions or sensitivities, 1,000,000 P&L points per list), the finite rule, structural `E_INPUT`, `E_DOMAIN`. | KR-68 | Outside-check classes for the wave 2 gate | A value case counts as outside-checked only if its expected output is (P) a number printed in a read source, (L) computed by an independent library (SciPy) from the inputs, or (B) re-derived by a blind lane under DR-H2 (`program/STAGE_H_BLIND_LANE.md`). ## Wave 2 lane A implementation rulings (K-8a, K-8f): PROPOSED

| KR-112 | Cash equity consistency | KR-51 says cash equity has notional equal to market value and the worked examples give it seniority `EQUITY`, but nothing says what happens otherwise. A position with `cash_equity: true` must have `seniority` `EQUITY` and `notional == market_value`; anything else is `E_DOMAIN` (checked with the KR-52 maturity rule). Reason: a stock has no face value and no seniority other than equity; accepting a mismatch would silently price it as a bond. Goldens drc_ke-0015, drc_ke-0016. |
| KR-113 | One bucket per obligor | Each position names its own `bucket`, but the offset of KR-53 is per obligor and the HBR is per bucket. An obligor whose positions name two buckets is structural `E_INPUT` (drc_ke-0013). |
| KR-114 | Output shapes and order | `drc_nonsec`: `positions` (`id`, `gross_jtd`, `weight`, `scaled_jtd`) sorted by `id`, `obligors` sorted by name, `buckets` in the order CORPORATE, SOVEREIGN, LOCAL_GOV (present buckets only). `drc_sec_nonctp` and `drc_ctp` (positions mode): `positions` (`id`, `weight`, `scaled_jtd`) sorted by `id`, `buckets` sorted by key (`wtd_long`, `wtd_short`, `drc`, and `hbr` for securitisations). Sorting is by Unicode code point. `rrao`: `instruments` (`id`, `weight`, `excluded`, `addon`) in input order. `imcc`: `classes` an object of numbers in the order IR, EQ, FX, COM, CS, `classes_floored` a list in the same order, `portfolio_floored`. With this, permuting the input leaves every output unchanged (A3 of `frtb-drc-rrao.md`). |
| KR-115 | One rw per netting group | `drc_sec_nonctp` nets by (`bucket`, `pool`, `tranche`) and `drc_ctp` by (`index`, `series`, `tranche`). A net amount needs one risk weight; positions netted together with different `rw` are structural `E_INPUT` (sec_ke-0006, ctp_ke-0006). The maturity weight is applied per position before netting, as the spec says for securitisations and CTP. |
| KR-116 | Empty inputs, labels | `drc_nonsec` needs 1 to 100,000 positions (spec input line); zero positions is `E_INPUT`. `drc_sec_nonctp`, `drc_ctp` (either mode) and `rrao` accept an empty list (result 0). A position with notional 0 and market value 0 is accepted and contributes nothing. In `drc_ctp` positions mode with no net amount, `hbr_ctp` is null (as KR-54) and every `DRC_b` is 0. Securitisation and CTP outputs carry both the KR-69 `label` and the KR-55 text, as `rw_source`. In `bucket_drc` mode the outputs are `drc`, `label` and `rw_source` only. |
| KR-117 | PLA arithmetic and the KS tail | Spearman: the Pearson correlation of average ranks computed on centred doubled ranks `2r - (n + 1)` (integers in [-(n-1), n-1], so every sum is exact in 64-bit integers up to n = 1,000,000), then `S_xy / sqrt(S_xx S_yy)` in binary64, clamped to [-1, 1]. `Q_KS(x)`: 1 when x <= 0; for 0 < x < 1 the equivalent theta series `1 - sqrt(2 pi)/x sum_k exp(-(2k-1)^2 pi^2 / (8 x^2))` (the alternating series converges too slowly there and diverges at 0); for x >= 1 the alternating series of KR-56; terms are added until one underflows to 0. Agreement with SciPy `kstwobign.sf` within 1e-12 relative is tested on a grid from 0.05 to 4. `risk.frtb.pla.ks_pvalue` needs `n >= 1` (`E_DOMAIN`, pla_ke-0010). |
| KR-118 | Liquidity horizon inputs | `risk.frtb.ima.lh` takes exactly one of `category` (a key of MAR33.12 Table 2), `fx_pair` (`AAA/BBB`, three capital letters each side, else `E_SCHEMA`) or `constituents` (non-empty list of `{weight, n}`); none or more than one is `E_INPUT`, as is an empty list. `fx_pair` gives 10 when specified (KR-60), else 20 (`FX_pairs`); the same currency twice is `E_DOMAIN`. A constituent weight below 0 or an `n` that is not one of 10, 20, 40, 60, 120 is `E_DOMAIN`. Optional `maturity_days` must be above 0 (`E_DOMAIN`). Outputs `n`, `table_n` (before FAQ4) and `rule` (`table`, `fx_pair` or `index`, with `+maturity` when FAQ4 shortened it). |
| KR-119 | Negative ES from a P&L list | KR-57 makes a negative `es_t` an error because the formula squares it. The same holds for an ES computed from a `pnl` list whose 2.5% tail is a gain: `E_DOMAIN` (es_ke-0006), not a silent floor at 0. An empty list gives ES 0 (KR-57, es_k-0005). |
| KR-120 | Capital inputs | `imcc_prev`, `ses_prev`, `imcc_avg`, `ses_avg`, `drc`, `c_u`, `sa_all`, `qualitative_addon` and each desk `sa` must be 0 or above (`E_DOMAIN`, cap_ke-0004, cap_ke-0005): they are capital amounts. Stated, not changed: with no desks at all, `SA_G,A = 0` and the formula of MAR33.43 adds `max(0, IMA_G,A - SA_G,A) = IMA_G,A` on top of the capped first term; the operation applies the formula as written. |
| KR-121 | RFET bucket inputs | `risk.frtb.rfet.bucket` takes `row` (A, B, C, D) and, for rows A to C, a maturity `t` in years, for row D an option `delta`; the other key absent. Wrong key, both or neither is `E_INPUT`; a negative value is `E_DOMAIN`. Output `bucket` (1-based), `lower`, `upper` (null for the open last bucket of rows A to C). |
| KR-122 | Spec wording corrected (A3 of `frtb-ima.md`) | A3 says "`es_lh` with a single nonzero horizon j gives ES_j sqrt(sum of weights up to j)". By the MAR33.4 formula a single nonzero ES_j gives `ES_j sqrt(w_j)` with w = (1, 1, 2, 2, 6). The sum-of-weights form holds when every risk factor has liquidity horizon LH_j, so that ES_1 = ... = ES_j = E and the rest are 0: then ES = E sqrt(LH_j / 10) (es_k-0002 is the case j = 5). Both properties are tested; the A3 sentence should be replaced by them. Also in `frtb-ima.md` Errors: "an LH class key repeated" cannot occur, since `classes` of `imcc` is a JSON object (a repeated key does not survive parsing); nothing implements it. |
