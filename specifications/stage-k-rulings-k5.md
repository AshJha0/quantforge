# Stage K, K-5 rulings (lock-free snapshots, real-time hedge): PROPOSED

Status: PROPOSED by lane k-v1-k5 on 2026-11-20. Not normative until the stage K coordinator confirms each row. Reviewer: none: self-assessment; no second review (owner decision 2026-11-18). Spec: `12-platform/lock-free-snapshots.md` 0.2.0-proposed. KR-280 to KR-286 are the K-5 rows KR-190 to KR-196 of the k-w3-spec proposal (`stage-k-rulings-w3.md` on branch `k-w3-spec`), renumbered because KR-190 onwards collides on `k-v1`; KR-283 and KR-285 are changed, KR-287 and KR-288 are new. Number block checked free with `git grep` over every remote branch on 2026-11-20.

| ID | Topic | Ruling |
|---|---|---|
| KR-280 | Snapshot publication (was KR-190) | Single writer, many readers, immutable fixed-size snapshot (72 bytes; at most 4 KiB is the rule). Java: release store and acquire load of a record with final fields through `AtomicReference`; the GC reclaims. C++ and Rust: single-writer hazard pointers [Michael 2004, recalled] over a fixed pool of R + 2 slots, 1 <= R <= 64 registered readers. Every build refuses a version that does not increase |
| KR-281 | Rejected designs (was KR-191) | `std::atomic<std::shared_ptr>` (not required lock-free), epoch-based reclamation (a stalled reader blocks reclamation), a third-party crate such as `arc-swap` (no new dependency), seqlock (readers block on a stalled writer, and the racing reads are data races under the C++ and Rust models). Python: correctness reference, not lock-free, stated in its module text |
| KR-282 | Progress claimed (was KR-192) | Writer wait-free (bounded scan of R hazards); reader lock-free, not wait-free; Java single-access on the JVM's terms. No heap allocation after construction in C++ and Rust. No time bound claimed |
| KR-283 | Risk and hedge content (changed from KR-193) | Writer per publish: `risk.intraday.delta_gamma_bound(book, h)`; `book_delta = fsum(-T (N exp(-(y + h) T)))`; `hedge_unit_delta = -T_H exp(-(y_H + h) T_H)`; `hedge_notional = -book_delta / hedge_unit_delta`. Replaces key-rate plus `hedge.greeks.neutralise` (a Black-Scholes option hedge, a different book from the zero-coupon book the snapshot measures). Library functions, not a CLI operation, so no goldens; a CLI operation is left |
| KR-284 | Exactness (was KR-194) | A number read through a snapshot is bit-identical to the direct call, 1,000 publishes per build; also checked on every 64th read inside the race test |
| KR-285 | Race tests (changed from KR-195) | C++ ThreadSanitizer, WSL and CI; Rust ThreadSanitizer on nightly in CI only (pinned 1.99.1 is stable), loom and Miri not used (loom is not a dependency); Java jcstress 0.16 in a Maven profile, quick mode locally, default mode in CI; Python threading reference. Scenario P = 20,000 default; long mode 1,000,000 at R = 1 and 4, 200,000 at R = 16 (time under ThreadSanitizer); R in {1, 4, 16} |
| KR-286 | Targets (was KR-196) | Table S1 to S5 of the spec, unchanged, fixed in this commit before any timing run; H-9 method; no measurement exists and none is claimed. Label "latency-aware analytics on simulated data; local laptop, not the acceptance machine" on any future timing |
| KR-287 | Shared scenario and checksum (new) | `datasets/scenarios/k5_snapshot.json` (generator `build_k5_snapshot.py`, `--check` mode): book, hedge, shift rule `((k * 7919) mod 401 - 200) * 5e-5`, expected values at ten versions from the Python build, compared at 1e-9 relative by every build. Checksum `c = rotl64(c xor w, 27) * 0x94D049BB133111EB` from seed `0x9E3779B97F4A7C15` over eight words; pinned values in the spec |
| KR-288 | Planted faults (new) | Selected by a test-only constructor parameter, default none: C++ and Rust `RelaxedPublish` and `SkipHazardScan` (ThreadSanitizer must report); Java in-place mutation (jcstress `InPlaceMutationFault`, graded ACCEPTABLE_INTERESTING, count recorded); all builds a corrupted field (reader check must fail). A race test counts as built only with its faults shown failing |
