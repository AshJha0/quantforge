# Stage F rulings

Spec version 1.0.0. Normative: this page is part of every stage F spec page and of every operation from earlier stages for the rules marked "all operations". It wins where it is more exact. Prefix F-.

## Wave 0: robustness and shape (all operations)

| # | Point | Ruling |
|---|---|---|
| F-1 | Non-finite tokens | A JSON input whose spec type is Real (including a Real inside an array or object, and a field that accepts a string or a number) may be one of the exact, case-sensitive strings `"NaN"`, `"Infinity"`, `"-Infinity"`. The build reads it as the binary64 NaN, +inf or -inf. Any other string in a Real field is `E_SCHEMA`, as before. The three strings in an Integer, 64-bit unsigned, Date, Instant or Enum field are `E_SCHEMA`. A number literal that overflows binary64 (such as `1e400`) stays `E_SCHEMA`. Reason: JSON cannot write NaN or infinity, and plan item E1 needs the domain check to be reachable from the CLI |
| F-2 | Finite rule (E1) | Every public numeric input must be finite. The first rule check of every operation, after `E_PARSE`, `E_SCHEMA` and `E_LIMIT` and before any check its own spec lists, walks all Real inputs (depth first, in document order) and returns `E_DOMAIN` on the first that is NaN or infinite. This applies to every operation of every stage, and to optional Real inputs when present. Source: IEEE 754-2019 section 5.11 (every ordered comparison with NaN is false, so `vol < 0` lets NaN through) |
| F-3 | Negative zero | `-0.0` is finite and is the same input as `+0.0`: the result (status, error code, outputs within the case's tolerance) equals the `+0.0` result. A build must not branch on the sign bit of an input zero. Outputs may be either zero (`cli-contract.md`, value encoding) |
| F-4 | Library API | The rule also holds for every public function of the library API in each language: it checks F-2, or it is not public, or its documentation states "unchecked: caller guarantees finite inputs" (raw kernels such as Rust `black()` and `bachelier()`). The quality_gate name-map check (F-5) lists the unchecked kernels |
| F-5 | Name map (E4) | `specifications/name-map.json` is generated by `tools/gen_name_map.py` from the operation tables and is the cross-language map of public names. Shape: operation `<domain>.<area>.<verb>`; Rust and Python function `<area>_<verb>` in module `<domain>`; Java static method `<area>` + `PascalCase(<verb>)` (first letter lower case) in class `PascalCase(<domain>)`; C++ function `<area>_<verb>` in namespace `qf::<domain>`. Input keys keep their spec name, converted to camelCase in Java only. Keys that carry a unit keep it in the name (`_years`, `_bp`, `_pct`); a Real input with a unit and no suffix is a name-map defect, listed in the file under `unit_warnings` |
| F-6 | Convergence field (Q5b) | Every spec that defines an iterative, grid, quadrature, tree or Monte Carlo method has a section `## Convergence and limit cases` with an asserted order (and the sequence used to measure it) and at least one limit case with a closed form or independent reference. See `specifications/README.md` |

## Wave 1, F6 model fixes (R7, R8, R10)

| # | Point | Ruling |
|---|---|---|
| F-7 | Index option model (R7) | `credit.cdsindex.option_price` is Black on the Pedersen adjusted pair: `F_adj = F + FEP/A`, `K_adj = C + (K - C) A_K P(expiry)/A`. Front-end protection is inside the forward, never added to a price. Index options are never knocked out, so there is no `knock_out` input. `credit.cdsoption.price` (single name, E-B23) is unchanged: it stays the QuantLib-matching single-name convention and is not for index options |
| F-8 | Strike annuity (R7) | `A_K` is the stylised annuity (E-B22 legs) from `expiry` to `maturity`, discounted to `expiry` at the index `rate`, on the flat hazard `h_K` that makes the stylised spread from `expiry` equal `K`. Same recovery as the index. The ISDA standard model's upfront conversion is the market's version of this; the stylised legs keep the operation self-contained and are what the goldens pin |
| F-9 | Discounting the exercise upfront (R7) | `G` is paid at expiry whatever has defaulted (no knock-out), so it is discounted by `P(expiry)` only, not by survival |
| F-10 | Domain (R7) | `F_adj <= 0` or `K_adj <= 0`: `E_DOMAIN`, after the input checks. `vol = 0` gives intrinsic value, not an error |
| F-11 | GARCH estimate optimum (R8) | Interior maximum only; Newton-polished to a relative step below 1e-12; boundary or non-maximum: `E_NO_CONVERGENCE`. Parameters compared at 1e-6 relative |
| F-12 | Demeaning (R8) | Two-step: the sample mean is removed and held fixed; it is not a likelihood parameter and has no standard error. `"SAMPLE"` initial variance uses the demeaned returns |
| F-13 | Standard errors (R8) | Observed information `(-H)^{-1}` at the optimum, in the parameters as reported (`omega`, not a scaled `omega`). No sandwich, no expected information |
| F-14 | Student-t scale (R8) | Innovations are t with unit variance (`nu - 2` in the density), `2 < nu <= 500`. `nu` is estimated with the other parameters |
| F-15 | VIX null quotes (R10) | A quote may be `null`. A null series is not an ATM candidate (only strikes with both sides non-null are), is removed from its own side's walk before it starts (no effect on zero-bid runs), and at `K0` makes the term `E_INPUT`. Source: Cboe Mathematics Methodology v5.0, 3(a)(ii) and (iii), quoted in `vix-index.md` |
| F-16 | VIX crossed quotes (R10) | A bid above its ask stays `E_INPUT` (Cboe leaves crossed series to its quote-history filter, which a pure function cannot run) |
| F-17 | Local vol at slice expiries (R10) | Documented, not changed: `w`, implied vol, `w_k`, `w_kk` are continuous in `T`; local vol jumps at each slice expiry by the stated formula, and a node takes the right limit. A C1-in-`T` surface is stage G model work |

## Wave 1, F1 curve layer (Q1, Q4, funding)

| # | Point | Ruling |
|---|---|---|
| F-18 | New interpolations (Q1) | `MONOTONE_CONVEX`, `MONOTONIC_LOG_CUBIC`, `TENSION_SPLINE` (with `tension`) and `HYBRID` (with `step_end`), all on `S = D/J`. New operation `rates.curve.inspect` reports instantaneous forwards |
| F-19 | Convex monotone positivity (Q1) | QuantLib `ConvexMonotone(0, 1, forcePositive = false)`. QuantLib's forcePositive helper does not preserve section averages, so a curve built with it does not return its own pillars; measured on the stage F pillars and recorded in `curve-framework.md` |
| F-20 | Extrapolation of the new methods (Q1) | Flat instantaneous forward `f(t_n-)` beyond the last pillar. `LOG_LINEAR_DF` and `LINEAR_ZERO` keep their stage B rule |
| F-21 | Bootstrap with non-local methods (Q1) | `SEQUENTIAL` and `GLOBAL` both return the global solution, repricing below 1e-13 |
| F-22 | Locality is on pillars (Q1; amends the T row) | Locality is stated for a change in one pillar discount factor, not in one quote, because a bootstrap spreads a quote move over later pillars. The T row's "1 bp move in quote i" becomes "a change in pillar i", and its "forced positive" becomes `forcePositive = false` (ruling F-19) |
| F-23 | Outside-oracle floor for stage F | The 60% floor (rule 11.2.5, as stage D) is measured over the stage F value suites. The E1 suites (`e1_*`) are left out of the denominator: they test the input rule F-2 on every older operation, and no library is an oracle for a JSON input rule. A published worked example by the owner of a methodology (Cboe for VIX, BCBS for FRTB-SA) counts as outside when every compared output matches its printed digits. `oracle/python/outside_f.py` writes `oracle/outside_register_f.json` and prints the share |
| F-24 | Joint solve unknowns (Q4) | One pillar (ln D) per non-turn instrument on pillar curves; base and step rates on `OIS_STEPS`; ln factor per turn, pinned by the instruments marked `"turn": true` (as many as turns). Unknown order and labels as `joint-solve-and-funding.md`; they are the Jacobian's rows |
| F-25 | Block structure (Q4) | Curves are given in dependency order; `dR/dx` is block lower triangular, and Jacobian entries for an earlier curve's unknown against a later curve's quote are exactly 0. A block-by-block solve is allowed |
| F-26 | Turn sensitivity (Q4) | `d model / d ln factor` with other unknowns held; exactly 0 for an instrument whose dates all lie on one side of the turn date (a factor applies to dates strictly after it, so both legs of such an instrument scale together or not at all). Amended 2026-11-10 (from the Rust lane): this holds exactly on `OIS_STEPS` curves. On a pillar curve the unknowns are full `ln D` at pillars, so moving the turn changes `S = D/J` at pillars after it and can move a non-spanning instrument inside the section that crosses the turn; the output is then the honest `d model / d ln factor` (the `dR/dx` column), not a forced 0. The goldens hold the honest values: in the four-curve case `SOFR-1M`, which ends before the turn, has a turn sensitivity of about -0.023 |
| F-27 | Futures in the joint solve (Q4) | The model rate is the simple rate `(D(s)/D(e) - 1)/alpha` on ACT/360 (compounded SOFR on a curve); the quote is the price, and its Jacobian column uses `d residual / d price = 0.01 e^{-z}`. Convexity parameters are inputs, not solved |
| F-28 | Jacobian of a piecewise interpolation (Q4) | The IFT Jacobian is the derivative of the solution at the solution point. Monotone convex is piecewise in its data (Hagan and West's four regions), so the solution is not smooth everywhere in quote space; the golden check uses a bump-and-rebuild reference whose step is proved sound: halve `h` from 1e-4 until no interior section changes region under any bump of `+-h` or `+-h/2`, and the `h^4` error estimate of the Richardson value, `|R(h) - R(h/2)| / 15`, is below half the `jacobian` tolerance. The first and last sections sit at `g1/g0 = -2` and `-1/2` exactly by the endpoint rule, where adjacent regions give the same function, so a rounding flip there is not a kink. Measured on the full four-curve system: at `h = 1e-4` the reference is off by 2e-3 (a kink about 6e-5 away in the SOFR-2Y quote); at 2e-5, 1e-5, 5e-6 the error falls as `h^4` (6e-7, 3e-8, then 5e-10, inside the tolerance); below that, bump noise of about 1e-9 sets the floor, which is why convergence is judged by the error estimate rather than by two estimates agreeing. A build's own `dR/dx` stencil can straddle a kink too: the Rust lane found a fixed five-point 1e-5 stencil off by 7.5e-4 on turn / SOFR-1M (0.11714 against 0.11790), while the oracle's Richardson 1e-5 / 5e-6 central differences give 0.1178976 and pass the reference. A build should use a stencil that is checked for this (Rust shrinks it per column until two steps agree) |

## Wave 2, F3 sensitivities and F4 portfolio risk

| # | Point | Ruling |
|---|---|---|
| F-29 | AAD as a reference method (F3, Q3a) | ADR-0010 (bump and revalue only) stays the rule for every older risk operation. `risk.book.ois_sensitivity` defines its outputs as exact derivatives; Rust computes them by reverse-mode AAD through the IFT, the other languages by any exact method (closed form or forward-mode duals). Central differences on the unknowns do not meet the T row's 1e-8 relative bound with margin and are not allowed for this operation |
| F-30 | Structural zeros of the zero Jacobian (Q3a) | On a sequential build (`LOG_LINEAR_DF`, `LINEAR_ZERO`) an earlier pillar does not depend on a later quote; those entries are exactly 0 in the goldens and the `ift_jacobian` absolute term (1e-11) passes only values within 1e-11 of 0 |
| F-31 | VaR order statistic (F4) | `k = ceil(n c)` with `n c` the binary64 product; VaR is the `k`-th smallest loss and ES the mean of the losses from the `k`-th up, VaR scenario included (Hyndman and Fan type 1). Chosen because it matches `numpy.quantile(method="inverted_cdf")`, an outside check, and gives the third-largest of 250 losses at 99%, the usual reading of the Basel 99%/250-day rule |
| F-32 | Likelihood ratios near 0 (F4) | An LR below 1e-12 is exactly 0, with p-value 1. An LR that is 0 in exact arithmetic (exceptions equal to `n p`, or independent transitions) comes out near 1e-15 in binary64, and the chi-square tail near 0 moves as `sqrt(LR)`, which would cost 1e-7 in the p-value |
| F-33 | GIRR delta parameters (F4) | From MAR21 (in force 2023-01-01, BIS page of 2026-03-23). The tenor correlation formula is an image on the page; it is accepted because it reproduces the printed Table 2 of MAR21.46. The `low` scenario formula `max(2 rho - 1, 0.75 rho)` is an image with no printed table to check it: recorded as a known issue for a human with the PDF |

## Wave 3, F5 book and use case 4

| # | Point | Ruling |
|---|---|---|
| F-34 | Position cost rule (F5) | Weighted average cost; a reduction realises `sign(q) c (p - a)` on the closed quantity `c`; a reversal through 0 opens the remainder at the trade price. Expiry and default are trades at the settlement or recovery price; a roll closes one instrument and opens the next at the stated prices. Marks fall back by source priority on the day, then to the most recent quote within `max_age_days` |

## Lane questions, 2026-11-10

| # | Point | Ruling |
|---|---|---|
| F-35 | Tension spline small-`z` series (C++ lane) | The spec's `alpha = h/6 (1 - z^2/60)` was wrong: from `1/sinh z = 1/z - z/6 + 7 z^3/360`, `alpha = h/6 (1 - 7 z^2/60)`. `R(u)` gains its `z^2` term, `(u/h)(u^2 - h^2)/6 (1 + sigma^2 (3 u^2 - 7 h^2)/60)`, since its leading term alone is off by `z^2` (1e-6 relative at `z = 1e-3`). `beta` was right. **Amended after the R5 audit:** the claim that no golden reached `z < 1e-3` was wrong (tension 0.01 on a 1/12-year interval is `z = 8.3e-4`), and the exponential stable forms above `1e-3` still lose `epsilon / z^2` (4e-8 relative at `z = 1e-3`). The spec now uses cancellation-free forms in `shm(x) = sinh x - x` and `chm(x) = cosh x - 1` for `z < 1`, with no series threshold in `z`. `curve_f` is regenerated: the tension spline cases change in their last digits |
| F-36 | Cross gamma and OIS `side` (Rust lane) | `risk_f3` spells `side` as `PAY` and `RECEIVE`, as `ois-curves.md` and every older OIS golden do (it had `PAYER` and `RECEIVER`). The cross gamma cases carry a limit of 1e-9 absolute (1e-8 relative): at 1 bp on a 1e6 notional the four-point formula loses about 1.5e-10 to cancellation in binary64 |
| F-37 | Local vol continuity bound (Java lane, F-J7) | The property test's bound becomes `1e-9 (T_j |w_T(T_j-)| + w(T_j))`: a step of `1e-9 T_j` moves `w` by `1e-9 T_j w_T`, so `1e-9 w(T_j)` failed wherever the left slope exceeds `w/T`. Property test only; no golden changes |
| F-38 | F-1 tokens outside Real fields (Python lane F-Q3; C++ and Java noted) | The three strings become numbers only in a Real-typed field, and at the top level of a field whose value is any JSON (`core.store.*` record `value`, read as a Real and refused by F-2), as C++ (in its stage F notes) and Java (F-J1) do. In a string-typed field (ids, names, labels) they stay strings. Nested inside an any-JSON value they stay strings. Python changes to match; no golden tests it |
| F-39 | F4 and F5 gaps (C++ lane, Java lane) | `risk.var.monte_carlo` `seed` is a decimal u64 string, as every other seed in the contract (the goldens had a JSON integer; regenerated). A covariance whose Cholesky meets a non-positive pivot is `E_NOT_POSITIVE_DEFINITE`, the existing code (the golden had `E_DOMAIN`; regenerated). Accepted as the C++ lane proposed: FHS with all returns 0 is `E_DOMAIN`; traffic light with exceptions above observations is `E_DOMAIN`; a duplicate opening position is `E_INPUT` and a zero opening quantity is ignored; `ipv` is optional; a quote after `as_of` is never a mark; use case 4 checks shapes (`factor_names` length, ragged rows) before `T >= K + 2`. Spec texts updated |

## R5 audit findings, 2026-11-10 (coordinator ruling: error cases stay in the outside-oracle denominator; the 60% floor is recorded as failed)

| # | Point | Ruling |
|---|---|---|
| F-40 | Four-curve Jacobian (`joint_f-0001`) | Its `jacobian` and `turn_sensitivity` use a new class `jacobian_piecewise` (1e-7 absolute, 1e-5 relative). The IFT golden differs from the bump-and-rebuild reference by at most 3.2e-9; the reference (Richardson at `h = 6.25e-6` and `h/2`) is stored in `oracle/Q4_REFERENCE_F.json` as a second, independent value. Builds whose stencils pass the kink checks differ by about 2e-8 (Rust, measured); a kink-straddling error is 5e-4 or more. The bound sits 30 times above the first and 5,000 times below the second. The other three systems keep `jacobian`. **F-25 zeros are exact in the goldens** (the generator zeroes the LU's rounding after asserting it is below 1e-12) and are checked with the runner's `exact_zero` method. **`E_NO_CONVERGENCE`:** Newton stops at `max |R| < 1e-13`; if `dR/dx` is singular at an iterate (reciprocal condition below 1e-14), or 50 iterations do not get there, the result is `E_NO_CONVERGENCE` (golden: two instruments on the same dates with different quotes) |
| F-41 | Silent choices on the book operation | `risk.book.ois_sensitivity` accepts only the sequential builds `LOG_LINEAR_DF` and `LINEAR_ZERO` (F-30 needs them); any other `interpolation` is `E_INPUT` (Rust's choice; C++ had `E_DOMAIN`). `tenor_years` must be in `[1, 100]`, else `E_DOMAIN`. Goldens added for both |
| F-42 | `E_LIMIT` sizes for the stage F operations (checked after `E_SCHEMA`, before the finite rule) | swaps per book 10,000; PCA tenors 200 and observations 100,000; cross gamma pillars 100; P&L or return series 1,000,000; Monte Carlo paths 10,000,000 and assets 100; exception series 1,000,000; GIRR sensitivities 100,000; lifecycle events 1,000,000 and positions 100,000; mark instruments 100,000 and quotes per source 1,000,000; use case 4 observations 100,000 and factors 50. Goldens for the two cheap ones (201 PCA tenors; 10,000,001 paths) |
| F-43 | GARCH estimate | Parameters are judged at 1e-8 relative (1e-14 absolute; was 1e-6): Newton on an exact score until the relative step is below 1e-12 reaches about 1e-10. The interior margins are pinned: `omega / v >= 1e-6` with `v` the sample variance of the (demeaned) returns, `alpha >= 1e-6`, `beta >= 1e-6`, `1 - alpha - beta >= 1e-6`, and for Student-t `nu - 2 >= 1e-6` and `500 - nu >= 5e-4`. A maximum outside these margins, or a Hessian that is not negative definite, is `E_NO_CONVERGENCE`. Golden: returns of constant size, where every `(omega, alpha, beta)` with `omega = (1 - alpha - beta) c` gives the same likelihood (a plane of maxima, singular Hessian) |
| F-44 | Structural zeros | The runner gains `extra_checks` method `exact_zero` (`output` a dotted path to a matrix, `positions` a list of `[row, column]`); each position must be exactly `0.0` or `-0.0`. Used for F-25 (`joint_f`), the F-26 zeros on `OIS_STEPS` and F-30 (`risk_f3` zero Jacobian above the diagonal). The values near 1e-26 in `risk_f3-0005` are not structural: that swap's fixed rate is its par rate rounded to binary64, so `(par - K) dA/dq` is genuinely about 1e-26, which the tolerance passes |
