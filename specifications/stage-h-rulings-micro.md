# Stage H rulings, wave 2 microstructure estimators and venue analytics: 2026-11-18

Written 2026-11-18 by the H-4b / H-16 spec lane under the owner's delegation. Numbers start at HR-70 so they cannot clash with a parallel wave-2 lane that continues from HR-59. Covers `09-microstructure/micro-estimators.md` and `10-execution/venue-analytics.md`. Append-only.

| # | Point | Ruling |
|---|---|---|
| HR-70 | Recovery criterion (14.7 H-4) | An estimator passes on one seed when `\|theta_hat - theta\| <= 3 SE_hat`. Fixed seeds are stated in the spec before any run; a failing seed is reported, never replaced. The coverage run uses 200 stated seeds and passes with at most 4 misses: under a correct estimator the miss probability is about 0.0027 per seed and P(more than 4 misses of 200) = 2.4e-4 (Binomial, computed 2026-11-18 before any run), so the gate can pass. Correction 2026-11-19 (audit HA-21): 0.0027 holds for the normal-approximation estimators only. The OLS tests use a t distribution: resilience (21 points, 19 df) misses with probability about 0.0074 per seed, so P(more than 4 of 200) is about 0.017; liquidity decay (29 df) about 0.0053; regime impact about 0.0049 (the audit's scipy figures). The gate and its threshold are unchanged and still passable |
| HR-71 | Random numbers | Simulations are Python-oracle only: `numpy.random.default_rng(seed)` (PCG64), draws in the order the spec lists. Other languages implement the deterministic estimators and are compared on the `mest_h-*` and `venue_h-*` goldens only; no cross-language random stream is promised |
| HR-72 | Markout sign and mid lookup | Markout is from the fill owner's side: `s (m(t+h) - p)`, positive when the mid moved in the owner's favour. Toxicity is the quantity share of fills with a strictly negative markout. The mid at time `u` is the last mid stamped at or before `u` (step function) |

| HR-74 | Degenerate fits | An exact fit gives SE 0 and is a valid golden; recovery tests use noisy simulations only, so SE 0 never decides a 3 SE test. Fewer observations than the estimator's stated minimum is `E_INPUT` |
| HR-75 | Error precedence (post-blind 2026-11-18; amended the same day so that HR-66 governs) | AMENDED 2026-11-18 (coordinator decision): HR-66 governs, and this ruling now only applies it. The order is `E_SCHEMA`, then structural `E_INPUT` (empty or short lists, unequal lengths, ordering, enum, cross-field consistency such as filled > sent or a missing regime label), then `E_DOMAIN`, then `E_LIMIT`. Reason: consistency with rulings B11, C15, C17, D53, R1-4 and HR-58, which already put structural checks first; HR-75 had the opposite order. Value-dependent `E_INPUT` checks (no cancel, sum x^2 = 0, all t equal, no mid at or before a lookup time) need valid values and stay after `E_DOMAIN`. Re-derived goldens: venue_h-0008 is now `E_INPUT` (filled > sent is cross-field, before the negative horizon); mest_h-0006 is now `E_INPUT` (two points, fewer than 3, before S_i <= S_inf). Both are hand re-derivations; mest_h-0006 was blind-checked under the old order and that verdict no longer applies The original text (`E_DOMAIN` before `E_INPUT`) is withdrawn |
| HR-76 | Venue analytics arithmetic (coordinator decision 2026-11-18) | Every input number of `exec.venue.analytics` is the decimal of its shortest round-trip form. The sums `sum s q (m(t+h) - p)`, `sum q`, `sum q p`, `sum q [indicator]`, `sum filled`, `sum sent`, the time sums `t + h`, the mid-time comparisons and the sign test are exact and unbounded: no digit cap and no context rounding (a 28-digit decimal context is wrong). HR-57's 36-digit range applies to the book, lit and SOR engines only, not here. Each output is then one division of two exact decimals (`markout` = N / Q, `markout_bps` = 10^4 N / P, `toxicity` = T / Q, `fill_rate` = F / S), rounded once to the nearest binary64, ties to even; there is no other rounding. Java BigDecimal, C++ and Rust unbounded integer decimals, Python `fractions.Fraction`. Because the result is correctly rounded, venue_h-0010 is compared at 1e-12 relative with absolute 0, so that a 28-digit implementation (which returns 0 there) fails |
