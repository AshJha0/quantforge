# Stage K ruling on the wrong-way-risk root (KR-257)

Written 2026-11-20 by the lane `k-v1-wwr`. **Status: CONFIRMED** by the stage K coordinator under the owner's delegation, 2026-11-20 (proposed the same day by the lane). Separate file so the branches merge without conflict. Source: a mutation lane (`k-v1-xvakill`) found that `xva.wwr.cva_hw` (G-44, `06-risk/xva-framework.md`) returns an unconverged root without an error; this lane reproduced it, mapped the failing region and wrote the fix.

## What was wrong

**Plain idea.** For each time bucket the operation solves one equation for a level `a`: the average survival over the paths must equal the survival curve. The old solver started Newton's method at `a = ln h` with no finite bracket. When `|b V|` is large the function is almost flat at the start, so the first Newton step jumps by `e^x / x` (with `x = h e^(bV) dt`), and 200 bisection steps cannot come back from there. Nothing checked the answer, so a wrong number came out.

**Measured (Python and Rust, commit c5afb2ba; four-build probe `_h4ci/probe/run.py`).** `times = [1, 2]`, two paths with `V = 10` throughout, `D = [0.97, 0.94]`, `h = 0.01`, `R = 0.4`, `b = 1`: returned `a = [-2.56e33, -2.53e33]`, `cva = 0`. Exact (closed form below): `a = ln 0.01 - 10 = -14.605170185988092` in both buckets, `cva = 0.11347051247504984`. One bucket, one path, `t = 1`, scanned over `b V` in steps of 0.25 from -50 to 50 (Python): the root is right only for `b V` in about `[-6.5, 9.25]` at `h = 0.01` (`[-6.5, 8.0]` at 0.03, `[-7.25, 4.25]` at 2, `[-10.25, 1.25]` at 40). Above that window the result is silently wrong; below it `exp` overflows in Python (raised; the CLI reports it as `E_NON_FINITE`). At `h = 1e-10` every case is wrong to about 2e-6 in `a`, because `mean_p S_p - e^(-h t)` cancels. Java (pure Newton) returned `E_NON_FINITE` for most large `|b V|`; C++ bracketed `a` in the fixed interval `[-800, 50]` and was right inside it, wrong outside it (for example `b V = -60`, root 55.4). The existing goldens `wwr_g-0001` to `-0004` (`|b V| <= 2.7`, `h = 0.03`) lie inside the window in every build, so they passed. Evidence class: measured.

**Closed form for identical V on every path (derivation).** If every path has the same `V_i`, every path has the same survival `S(t_(i-1))`, so the bucket equation `mean_p S_p(t_(i-1)) exp(-exp(a_i + b V_i) dt_i) = e^(-h t_i)` reads `S(t_(i-1)) exp(-exp(a_i + b V_i) dt_i) = e^(-h t_i)`. By induction `S(t_(i-1)) = e^(-h t_(i-1))`, so `exp(a_i + b V_i) dt_i = h (t_i - t_(i-1)) = h dt_i`, hence `a_i = ln h - b V_i` and `CVA = (1 - R) sum_i D_i max(V_i, 0) (e^(-h t_(i-1)) - e^(-h t_i))`. For the example: `0.6 x 10 x (0.97 (1 - e^-0.01) + 0.94 (e^-0.01 - e^-0.02)) = 0.11347051247504984`.

## Ruling

| # | Point | Ruling | Evidence |
|---|---|---|---|
| KR-257 | The G-44 root `a_i` for large `|b V|`, tiny and large hazards; what the operation does where no root can be given | **(1) Equation.** Each bucket solves the G-44 equation in the equivalent form `sum_p S_p (1 - e^(-x_p)) = (1 - e^(-h dt)) sum_p S_p` with `x_p = exp(a + b V_p(t_i)) dt` and `S_p = S_p(t_(i-1))`; when `1 - e^(-h dt) > 1/2` it uses the survival form `sum_p S_p e^(-x_p) = e^(-h dt) sum_p S_p`. In exact arithmetic this is G-44 divided through by `mean_p S_p(t_(i-1)) = e^(-h t_(i-1))` (the previous bucket's root); in binary64 it has no cancellation (`expm1`), so tiny hazards keep full precision. Bucket CVA is `D_i mean_p max(V_p, 0) S_p (1 - e^(-x_p))` and `S_p(t_i) = S_p e^(-x_p)`. An `exp(a + bV)` above `e^709` is taken as infinite (survival 0, default probability 1, derivative 0), so nothing overflows to NaN. **(2) Bracket.** `[ln h - max_p b V_p - 1, ln h - min_p b V_p + 1]`: every path's default probability is increasing in `a`, and at `a = ln h - b V_p` path `p` has default probability exactly `1 - e^(-h dt)`, so the left end gives a value below the target and the right end above it; the margin of 1 makes the sign survive rounding. No bracket expansion is needed, so there is no expansion cap and no `E_NOT_BRACKETED`. **(3) Iteration.** Safeguarded Newton (Numerical Recipes `rtsafe`): start at `ln h - (S-weighted mean of b V)`, take the Newton step only if it stays inside the current bracket and is at most half the step before last, else bisect; stop when a step is at most `1e-15 max(1, |a|)`; at most 200 steps, else `E_NO_CONVERGENCE` (not reached in any test or scan: the bracket is at most 1,403 wide, 61 bisections alone reach 1e-15, and a Newton step is taken only when it at least halves the step before last). **(4) Limits, checked after the G-44 domain checks, in this order.** `|b V_p(t_i)| <= 700` for every path and time, else `E_DOMAIN` (field `wwr_b`): above it the rounding of `a + b V` alone, `eps |b V|`, exceeds 1.6e-13 relative in the hazard and the 1e-12 relative CVA tolerance can no longer be promised, and `e^(b V)` leaves the binary64 range at 709.8. Then for every bucket `e^(-h t_i)` and `1 - e^(-h dt_i)` must be normal binary64 numbers (at least 2.2250738585072014e-308), else `E_NON_FINITE` (field `hazard_rate`): below that the survival target or the bucket default probability has lost precision or is 0, and the root is at minus or plus infinity in binary64. The limits are inclusive (`|b V| = 700`, `h t = 708` run). | Goldens `wwr_g-0007` to `-0026` (20 new, `gen_stage_g_w4b.py`, 130-digit mpmath bisection on the same bracket to 1e-40; seven identical-V cases asserted against the closed form); tests `python/tests/test_wwr_root_kr257.py`, `rust/.../tests/kills_xva.rs`, `cpp26/tests/test_short_rate_exotics_xva.cpp`, `java25/.../WwrRootTest.java` |

**Behaviour change of a released operation.** `xva.wwr.cva_hw` shipped in v0.7.0. Results inside the old working window move by at most 1.9e-15 relative on `wwr_g-0001` to `-0004` (Python; tolerance 1e-12); outside it, wrong numbers become right numbers, and two inputs that ran before now return errors: `|b V| > 700` (`E_DOMAIN`) and a survival target or bucket default probability below the smallest normal double (`E_NON_FINITE`). For `h = 1e-310` the old C++ and Java builds happened to return the right root; KR-257 makes that input an error in all four builds, because a subnormal default probability no longer carries 15 digits.

**Not changed.** The G-44 model, the tolerances (`root_finding`, 1e-9 absolute plus 1e-12 relative for the goldens; 1e-14 relative for the root), the outputs and the other error codes. A known difference that predates this ruling and is left as it is: `times[0] <= 0` is `E_INPUT` in Python and Rust and `E_DOMAIN` in C++ and Java (no golden sends it). Resolved by KR-258 (`stage-k-rulings-xva-errors.md`, proposed 2026-11-20): `E_INPUT` in all four builds, with goldens.
