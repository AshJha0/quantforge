# Stage J rulings, wave 3 (spec lane)

Normative for stage J (v0.9) wave 3: the G18 scenario stress engine and historical shock library, the leave-one-out and held-out-strike interpolation backtests, and the A3 drift detectors. A separate file from `stage-j-rulings-w1.md` and `-w2.md` so branches merge without conflict. Wave 1 and wave 2 rulings still hold where they are general (check order, limits before rules, F-2 finite inputs).

Owner decision 2026-11-15: wave 3 is Option C, all in v0.9.0. This file and the three spec pages were committed **before** any Treasury file was downloaded for wave 3, any backtest was run or any drift path was drawn (pass rules first, plan 14.10).

| J-W3-8 | Leave-one-out | For each interior knot `i = 1 .. n-2`, the interpolant is built on the other `n-1` knots with `core.interp.evaluate` conventions (`linear`, `log_linear`, `cubic_natural`, `monotone_pchip`) and evaluated at `x_i`; `error_i = fitted - y_i`. End knots are not left out (that would be extrapolation). `n - 1` must reach the method's minimum knot count and `n >= 3`, else `E_INPUT` |
| J-W3-9 | Held-out strikes | `surface_holdout` interpolates total variance `w = sigma^2 T` in log-moneyness `k` per expiry on the kept strikes, and converts back `sigma = sqrt(w / T)`; error in vol units `sigma_fit - sigma_true`. Held-out indices must be interior (not the first or last strike), distinct and sorted, else `E_INPUT`. Interpolated `w <= 0` is `E_DOMAIN` |
| J-W3-10 | CUSUM | Standardised `z_t = (x_t - mu0) / sigma`; `S+_t = max(0, S+_{t-1} + z_t - k)`, `S-_t = max(0, S-_{t-1} - z_t - k)`, both starting at 0. Alarm at `t` when `S+_t > h` (direction `+1`) or `S-_t > h` (`-1`; if both, `+1`). After an alarm both sums restart at 0 (`reset`, default true); with `reset = false` only the first alarm is reported |
| J-W3-11 | Page-Hinkley | From the last restart `r`: `xbar_s` the mean of `x_r .. x_s`; up-test `m_t = sum_{s=r..t} (x_s - xbar_s - delta)` (each term uses the running mean at its own step; with `xbar_t` in every term the sum would be `-(t - r + 1) delta` identically, a slip corrected on 2026-11-15 before any code ran), `M_t = min_{s<=t} m_s`, alarm when `m_t - M_t > lambda`; down-test symmetric with `-x`. `direction` input `up`, `down` or `both` (default). Restart after an alarm as J-W3-10. The running-mean form follows the usual data-stream statement ([GAMA14]) |
| J-W3-12 | PSI bins | `B` bins from the reference sample: edges `e_j = r_(ceil(j n / B))` (order statistics, 1-based, type 1 inverse empirical CDF), `j = 1 .. B-1`; bins `(-inf, e_1], (e_1, e_2], .., (e_{B-1}, inf)`. Proportions floored at `1e-4` (no renormalisation); `PSI = sum (a_j - r_j) ln(a_j / r_j)`. `alarm` when `PSI > threshold` (default 0.25). Tied edges give empty bins, which the floor handles |
| J-W3-13 | KS statistic and p-value | `D = max |F_n - G_m|` over the pooled sample, ties handled by evaluating both empirical CDFs after all equal values. Two-sided p-value `P(D' >= D)` under the continuous null: exact lattice-path count in integers (`D n m` is an integer), so the value is exact to binary64 rounding of one final division. Builds may count in fixed width while `C(n + m, n)` fits (Rust and C++: 128 bits) and otherwise use a binary64 walk that sums the exit probability (no `1 - stay` cancellation); that path is not exact, its relative error is a few ulps per lattice step, and golden `drift_j-0036` (n = m = 250, p about 4e-16) checks it at a pure relative limit of 1e-9 (audit 2026-11-15). Python and Java count in arbitrary precision. With ties the continuous-null p-value is still reported (conservative statement in the spec). `reject` when `p <= level` |

| J-W3-21 | CIR bond option with a finite but huge noncentrality (`rates.shortrate.capfloor`, `t_0 = 1e-10`, lambda about 1.9e11) | Before the Poisson series, every build applies the Chernoff bound: for `t < 1/2`, Markov's inequality on `e^(tX)` with the noncentral chi-square moment generating function `(1 - 2t)^(-k/2) exp(lambda t/(1 - 2t))` bounds the lower tail (`t < 0`) or the upper tail (`t > 0`) by `exp(f)`; the minimising `u = 1/(1 - 2t)` is `2x / (k + sqrt(k^2 + 4 lambda x))` and `f = (k/2) ln u - x (1 - 1/u)/2 + lambda (u - 1)/2` (Chernoff, Ann. Math. Statist. 23 (1952) 493-507; the MGF is Johnson, Kotz and Balakrishnan vol. 2 ch. 29). If `f < -750` the tail is below `e^-750 < 5e-324`, so the CDF is returned as exactly 0 (`u < 1`) or 1 (`u > 1`), the correctly rounded value: the error bound is one subnormal. A CDF the bound cannot settle with `lambda/2 > 1e5` is `E_LIMIT` (R6-8 work limit): there the series needs about `18 sqrt(lambda/2)` terms at incomplete-gamma orders near `lambda/2`, Python took 13 s at `lambda/2 = 1e6`, and the log weights lose digits to the `lgamma` cancellation. All golden CIR cases have `lambda/2` at most 2,110, and none is settled by the bound, so no golden value moves. Before: C++ capped the upward Poisson loop at 100,000 terms, under one Poisson standard deviation (about 220,000) at `lambda/2 = 9.3e10`, so its survival sums were truncated and the first caplet was 3690.6; Python's downward loop ran from the mode `9.3e10` towards 0 because its stop needed a positive sum; Java and Rust started at `j = 1e9` (a cap), where every weight underflows, and returned 0 for both CDFs, which is right here only by accident. Answer (exact to rounding): first caplet `N (P(0, t_0) - (1 + K tau_1) P(0, 2)) = 5790.068868782696`, first floorlet 0; a scipy `chndtr` convergence study over `t_0 = 1e-2` to `1e-12` approaches the same limit. Goldens `fuzzfix_j-0048` to `-0050` |
