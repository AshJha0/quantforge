# Bermudan sensitivity ladder at the default grid (stage K item K-8, R6-27)

Spec version 0.2.0. Status: **PROPOSED** (stage K wave 1). Rulings: `stage-k-rulings-w1.md` KR-8, KR-9, KR-18, KR-19. Depends on `04-pricing/short-rate-models.md` (G-18 scheme, unchanged) and `aad-core.md`.

**Plain idea.** The ladder of the pinned G-18 scheme is the exact derivative of a first-order scheme, and at the default grid that derivative is far from the model's: the price is within 0.2% but single ladder entries are off by up to 11%. Plan K-8 asks for every entry within 1% of the converged model derivative at the default grid. This spec says how, and why Richardson extrapolation alone is not the answer.

Two facts matter. (1) Several entries do not converge monotonically: aadladder_g-0002 entry 1 reads 87,159, 98,464, 102,352, 93,700, 96,435 on the five grids. (2) Even 801/400 is not converged for those entries (401/200 and 801/400 differ by 2.8%), so 801/400 cannot serve as the reference for a 1% test. The likely cause is the exercise boundary crossing grid nodes: the derivative of a pointwise `max` jumps when the boundary moves to the next node. A second-order time scheme alone does not remove that.

## Method `CN_RANNACHER_SMOOTHED` (KR-8 as revised by KR-18)

Version 0.1.0 of this method (cell average of the `max`, two implicit half steps, `alpha(t)` sampled at step ends) failed acceptance 3 on 18 entries (`oracle/K8_ACCEPTANCE_W1.json`). The causes and the measurements are in `program/K8_DIAGNOSIS.md`; the changes are ruling KR-18. This section is the full definition.

**Plain idea.** Three things keep a ladder entry from converging at second order. A curve node that falls inside a time step; an exercise decision that jumps from one grid node to the next as an input moves; and high-frequency error that Crank-Nicolson does not damp. The method removes the curve from the time stepping altogether, replaces the jump by a smooth weighting, and starts each interval with implicit steps.

1. **State, grid, knots.** As G-18 steps 2 and 3, written out here: `sx = sigma sqrt(g)` with `g = -expm1(-2 a t_m)/(2a)` (that is `(1 - e^{-2 a t_m})/(2a)`) and `t_m` the last exercise time; `h = width sx`; `dx = 2h/(nx - 1)`; `x_i = -h + i dx`, `i = 0..nx-1`; the centre node `i = (nx-1)/2` is the one read in step 6. Knots `0, t_1, ..., t_m` at the exercise times; interval `[t_(k-1), t_k]` gets `n = max(1, ceil(steps_per_year (t_k - t_(k-1))))` equal steps of size `dt = (t_k - t_(k-1))/n`, the product evaluated in binary64 as written (G-18 step 3). Every exercise date is a time-grid point by construction. The state variable `x` is the one of G-18 step 1, but this method never evaluates `alpha(t)` or the forward rate `f(0, t)`: the curve enters only through `ln P(0, s)` in steps 2 and 3.
2. **Scaled value.** The scheme carries `U(t, x) = V(t, x) D(t)`, `D(t) = exp(-int_0^t alpha(s) ds) = P(0, t) exp(-c2 I(t))`, with `c2 = sigma^2 / (2 a^2)` and `I(t) = t + 2 expm1(-a t)/a - expm1(-2 a t)/(2a)`. `U` solves `U_t = A U` backward in time with `(A U)_i = -(sigma^2/2)(U_(i+1) - 2U_i + U_(i-1))/dx^2 + a x_i (U_(i+1) - U_(i-1))/(2 dx) + x_i U_i`. `A` has no curve term and is the same at every step. `U(0, .) = V(0, .)`. `P(0, s)` is the input curve under the rule of `04-pricing/short-rate-models.md`, Conventions: `ln P` linear in time between the nodes `(0, 0), (t_1, ln DF_1), ..., (t_P, ln DF_P)`; beyond the last pillar the line of the last segment continues (flat forward); at a node time the value is the node's own. In formulas: for `0 < s`, take the segment `k` with `t_k <= s < t_(k+1)` (the last segment when `s >= t_P`), `w = (s - t_k) / (t_(k+1) - t_k)` and `ln P(0, s) = ln DF_k + (ln DF_(k+1) - ln DF_k) w` (with `t_0 = 0`, `ln DF_0 = 0`); `ln P(0, s) = 0` for `s <= 0`. Another algebraic form of the weight changes the result by rounding only. (Stated 2026-11-19 from the K-8 blind record, ambiguity 7; the reading is the one the goldens and all four builds use, `python/quantforge_core/bermudan_k8.py`; no value changed.)
3. **Scaled exercise value** at `t`, node `i`: `Ehat = phi (D(t) - Q(Tn) - K sum tau_j Q(Tj))` over the payments strictly after `t` (payment times `s > t`; a payment at `t` itself is excluded; `tau` as G-18 step 4), `Q(s) = exp(ln P(0, s) - c2 (I(t) + B e1^2) + c4 e2 B^2 - B x_i)`, `B = -expm1(-a (s - t))/a`, `e1 = expm1(-a t)`, `e2 = expm1(-2 a t)`, `c4 = sigma^2/(4a)`. This is `D(t)` times the G-18 exercise value; the forward rate cancels and does not appear.
4. **Time stepping.** A Crank-Nicolson step solves `(I + (dt/2) A) U_new = (I - (dt/2) A) U_old` on interior nodes; an implicit half step solves `(I + (dt/2) A) U_new = U_old`. Here `dt` is the step of step 1, so each implicit half step uses `dt/2` and the same matrix `I + (dt/2) A` as the Crank-Nicolson step. In each interval `[t_(k-1), t_k]`, the first interval `[0, t_1]` included, going backward from `t_k`, the first two steps taken (the two nearest `t_k`; all of them if the interval has fewer than two) are each replaced by two implicit half steps, four in all; the rest are Crank-Nicolson steps [Rannacher 1984 (not free, recalled); Giles and Carter 2006, section 1 and Table 1 (read 2026-11-19)]. (Stated 2026-11-19 from the K-8 blind record, ambiguity 3 and 5; the reading is the one the goldens and all four builds use, `python/quantforge_core/bermudan_k8.py`; no value changed.) Boundaries as G-18 step 5: `U_0 = 2U_1 - U_2`, `U_(nx-1) = 2U_(nx-2) - U_(nx-3)`, substituted into the first and last interior rows, then set after each solve. The explicit side `(I - (dt/2) A) U_old` applies the interior rows of `A` to the stored vector `U_old`, end values included; a Crank-Nicolson step is never the first step after an exercise date (the start-up half steps come first), so those stored end values are always the linear extrapolations set after the previous solve, and the result equals applying the boundary-substituted rows. (Stated 2026-11-19 from the K-8 blind record, ambiguity 2; the reading is the one the goldens and all four builds use, `python/quantforge_core/bermudan_k8.py`; no value changed.)
5. **Exercise smoothing** at `t_m` (with `U = 0`) and on arriving at each earlier exercise date (not at 0). With `f_i = U_i - Ehat_i`, `f_(-1) = 2f_0 - f_1`, `f_nx = 2f_(nx-1) - f_(nx-2)`:
   - `h_i = M(f_i, f_(i-1)) + M(f_i, f_(i+1))`, where `M(p, q) = int_0^1 (1 - u) max(p + (q - p) u, 0) du`: `p/3 + q/6` if `p >= 0` and `q >= 0`; `t - t r/3` with `r = p/(p - q)`, `t = p^2 / (2 (p - q))` if `p > 0 > q`; `q r^2 / 6` with `r = q/(q - p)` if `p < 0 < q`; 0 otherwise. The four cases are tested in the order written, on the binary64 values: `p = 0, q >= 0` takes the first (`q/6`, the value of the integral there), and `p = 0, q < 0` takes none of the first three and gives 0 (the integral is 0 there too); the derivative is that of the case taken. (Stated 2026-11-19 from the K-8 blind record, ambiguity 6; the reading is the one the goldens and all four builds use, `python/quantforge_core/bermudan_k8.py`; no value changed.)
   - End correction, for each `j` in `0..nx-2` in increasing order with `f_j > 0 > f_(j+1)` or `f_j < 0 < f_(j+1)`: let `pos` be the node of the pair with `f > 0` and `neg` the other, `rho = f_pos / (f_pos - f_neg)`, `d_i = f_(i-1) - 2f_i + f_(i+1)` for `1 <= i <= nx-2` and 0 at the two end nodes, `c = g m`, the product of the two numbers `g = rho (1 - rho)(2 rho - 1) / 12` and `m = (d_j + d_(j+1)) / 2`. The node coordinate `x_j` does not enter `c`; the end correction uses only `f` and its second differences `d`, taken from `f` before any correction, while `h` is updated pair by pair in increasing `j`. (Stated 2026-11-19 from the K-8 blind record, ambiguity 1; the reading is the one the goldens and all four builds use, `python/quantforge_core/bermudan_k8.py`; no value changed.) Then `h_pos -= (1 - rho) c` and `h_neg -= rho c`.
   - `S_i = h_i - (h_(i-1) - 2h_i + h_(i+1))/6` for `1 <= i <= nx-2`, `S_i = h_i` at the two end nodes (all `h` taken after the end corrections).
   - `U_i = Ehat_i + S_i`, at every node including the two end nodes, which are not re-extrapolated after smoothing; the next step reads only the interior nodes (it is an implicit half step), so the end values left by the smoothing never enter a solve. (Stated 2026-11-19 from the K-8 blind record, ambiguity 4; the reading is the one the goldens and all four builds use, `python/quantforge_core/bermudan_k8.py`; no value changed.)
   A node whose neighbours two away on each side all have `f > 0` keeps `U_i` to fourth order in `dx`, and one where they all have `f < 0` gets `Ehat_i` exactly: away from the exercise boundary this is the pointwise `max`. Sources: the hat function as the second-order smoothing operator, Kreiss, Thomee and Widlund 1970 (recalled, not read); cell averaging and its limits, Pooley, Vetzal and Forsyth 2003, sections 2.2 and 2.4 (read 2026-11-19); the end correction is derived in `program/K8_DIAGNOSIS.md` and measured there.
6. `price = notional x U` at the centre node at `t = 0`.
7. Ladder: the exact derivative of steps 1 to 6 with respect to each discount factor, `a` and `sigma` (`aad-core.md`). The grid of step 1 depends on `a` and `sigma` and is differentiated with everything else. An input the price does not depend on gives exactly 0: a curve node gets weight 0 in the interpolation of `ln P(0, s)` (step 2) at every exercise time and every payment time `s` exactly when no such `s` lies strictly between the node's two neighbours (the previous node, or 0 for the first; the next node, or no upper end for the last two nodes, whose segment continues beyond the last pillar). Examples: a node before the first exercise date when the next node is at or before that date; a node after the segment that holds the last payment. (Corrected 2026-11-19 by the K-8 blind packet review: the earlier wording "a curve node before the first exercise date with no node between, or after the last payment" was wrong for the node just after the last payment, whose entry is not zero because the payment's discount factor is interpolated from it.) Every comparison in step 5 (the four cases of `M`, the sign test of the end correction) is made on the binary64 value of the quantity; the derivative is that of the branch taken, so a constant (`1`, `2 rho - 1`, the `t` in `I(t)`) contributes nothing to a derivative. `d_price_d_discount_factors[j]` is per unit absolute change of the input `DF_j` (`aad-core.md`); a build that differentiates with respect to `ln DF_j` divides by `DF_j`. Forward (tangent) mode, reverse mode or any other exact differentiation of the same arithmetic gives the same ladder up to rounding; a finite-difference bump does not reach the golden tolerance below.
8. Richardson only through `num.richardson.check` (KR-9), never unguarded.

**Binary64 and tolerance (stated 2026-11-19 after the K-8 blind packet review; no value changed).** Plainly: the method is fixed down to every discrete choice, but not down to the order of floating-point operations, and the goldens allow for that. The order of additions and multiplications inside each formula, the form of the tridiagonal solve (the four builds use Thomas elimination without pivoting), and division against multiplication by a reciprocal are left open; they change results by rounding only. The goldens of this method (suite `stage_k/k8_k`) are compared as `|a - e| <= absolute + relative x max(|a|, |e|)` on the outputs as reported (scaled by `notional`), with class `aad_sensitivity` (absolute 1e-10, relative 1e-8) for every output of `rates.shortrate.bermudan_ladder` cases, price included, and class `root_finding` (absolute 1e-10, relative 1e-10) for `rates.shortrate.bermudan_swaption` cases (`conformance/tolerances/policy.yaml`).

**Worked example.** Three nodes with `f = (-1, 0, 1)`: `h_1 = M(0, -1) + M(0, 1) = 0 + 1/6`; `h_2 = M(1, 0) + M(1, 2) = 1/3 + 2/3 = 1` (with `f_3 = 2`); `h_0 = 0`. No end correction (no strict sign change between neighbours). `S_1 = 1/6 - (0 - 2/6 + 1)/6 = 1/18`. The pointwise value would be 0 and the cell average 1/8.

## `num.richardson.check` (guard helper, four languages)

Inputs: `values` `[f(h), f(h/r), f(h/r^2)]`, `ratio` r > 1, `assumed_order` p > 0. Outputs: `status` (`OK`, `ORDER_MISMATCH`, `NON_MONOTONE`), `observed_order` `log((f1 - f2)/(f2 - f3)) / log r` (null if the differences have opposite signs or one is zero), `extrapolated` `(r^p f3 - f2)/(r^p - 1)` when `OK`, else null. `OK` iff same-sign differences and `|observed - assumed| <= 0.5`.

## Limits

- **The 0.4986-year row is not judged.** Plainly: the ladder row of the curve node at 0.4986 years is not checked by any acceptance test. Under this method its value is exactly 0.0 on every grid, which is also the model's value (the price does not depend on that node). Acceptance 2 already leaves it out (below the 1e-3 floor) and acceptance 3 skips it under the rule it had from the first run, "an entry exactly zero on all three grids is not put through `num.richardson.check`". Owner decision 2026-11-19: the row stays skipped under that rule; no new ruling. The exact zero is checked only by the unit test named in the table above, not by an acceptance test. Example: case 0001, row 1 reads 0 / 0 / 0 on 201, 401, 801; the first definition read -337 / -105 / +11.

- **What QuantLib's number for that row measures (added 2026-11-19, `program/K8_ROW0_FINDING.md`; no rule, threshold or value changed).** Plainly: the reference file holds about -14.27 for this row of case 0001 (-10.00 and -9.59 for the other two), while the method gives 0. The two numbers are the same derivative, and the model's value of it is 0; QuantLib's number is the time-stepping error of its finite-difference engine. Side by side:

  | | This ladder (step 7) | QuantLib reference (acceptance 1) |
  |---|---|---|
  | Input moved | the discount factor `DF_1` of the node at 0.4986 years, alone | the same, by a relative bump of 1e-4 up and down |
  | Curve | `ln P` linear between nodes, rebuilt from the moved node | `DiscountCurve` (log-linear), rebuilt from the moved node |
  | Held fixed | `a`, `sigma`, every other discount factor, the schedule | the same; `HullWhite(curve, a, sigma)` with no calibration, nothing refitted |
  | Unit | per unit absolute change of `DF_1`, times `notional` | the same (the bump is divided by `2 h DF_1`) |
  | How the curve enters | only `ln P(0, s)` at the exercise and payment times 1, 2, ..., 6 years | the forward rate `f(0, t)` sampled at every time step |

  Formal statement: in the model the price is a function of `P(0, s)` at the exercise and payment times only (step 2 and step 3: `D(t)` and `Q(s)` are `P(0, t)` and `P(0, s)` times curve-free factors, and the operator `A` has no curve term). `DF_1` moves `P(0, s)` only for `0 < s < 1`, and no exercise or payment time lies there, so the derivative is exactly 0. QuantLib's engine instead integrates the forward rate step by step; a step that holds the node, or the forward read at the kink at 1 year, lets `DF_1` leak in at first order in the time step. Worked example (measured 2026-11-19, QuantLib 1.44, case 0001, xGrid 801): with the node on a time-grid point (tGrid 1,825, 3,650, 7,300, 14,600) the row reads +15.77, +7.88, +3.94, +1.97, halving with the step; with the node inside a step (tGrid 1,000, 2,000, 4,000, 8,000, 16,000) it reads -76.1, +25.5, -39.7, -14.3, -1.6. At the KR-19 grid 8,000 / 3,201 it is -14.274 and at 7,300 / 3,201 it is +3.95. The size, 4e-5 of the largest entry of the ladder, is the size of the reference's own error on the judged rows (its two bumps differ by 6 to 20 on rows 2 to 5 of the same case) and below the 1e-3 floor of acceptance 2. Bumping `DF_1` in this method by 1e-6 to 20% leaves the price bit-identical on 201/100 and 801/400 (measured, same file). The rows after 7.0055 years are 0.0 in both.

## Acceptance (fixed before any run; plan 14.8 K-8)

1. 2. At the default grid 201/100, every ladder entry of aadladder_g-0001..0003 with `|reference| >= 1e-3 max |reference|` is within 1% of the reference; `d_price_d_mean_reversion` and `d_price_d_sigma` too.
3. Observed order of the new method's price and ladder, by `num.richardson.check` on 201/401/801, between 1.5 and 2.5 with status `OK` on every entry. If any entry is `NON_MONOTONE`, step 3 of the method is not working and the test fails, whatever step 2 says.
4. The R6 use restriction is removed from docs and the model inventory only for `CN_RANNACHER_SMOOTHED`, only after 1 to 3 pass; G-18 goldens unchanged. **Done 2026-11-19 (KR-110):** 1 to 3 pass in all four builds (`oracle/K8_ACCEPTANCE_W2.json` (acceptance 1 to 3, Python; acceptance 3, Java), `oracle/K8_ACCEPTANCE_PORTS.json` (acceptance 3, C++ and Rust, values within 3.85e-14 of the row scale of Python), `program/STAGE_K_BLIND_K8.md` (blind re-derivation 7 of 7), `program/K8_ROW0_FINDING.md` (the 0.4986-year row, no bug), conformance on `k-r1` 2026-11-19); removed for `CN_RANNACHER_SMOOTHED` only; no golden changed.
