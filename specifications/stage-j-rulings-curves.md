# Stage J rulings, curves lane

Normative for the two curve families added in v0.9.0 by the curves lane: the financing term structure (`02-curves/financing-term-structure.md`) and the liquidity cost curve (`10-execution/liquidity-curve.md`). A separate file from the wave rulings so branches merge without conflict. Rules F-1 to F-3, F-5, F-6, R6-8.1 and the stage J check order (`E_PARSE`, `E_SCHEMA`, `E_LIMIT`, F-2, then each page's list) apply. Append-only; an amendment is a new row that names the row it amends.

| # | Point | Ruling |
|---|---|---|
| J-C-1 | Operations and contract | Adds `repo.term.curve`, `eq.forward.term_financed` (`02-curves/financing-term-structure.md`) and `liq.curve.cost` (`10-execution/liquidity-curve.md`). No new error code; the general per-array limit applies. Contract 1.15.0 (new operations are a minor version), reported by all four builds and expected by the runner. **Coordinator:** the stage J wave 3 lane may also take 1.15.0; at merge keep one number for the union (1.15.0 if only one lane bumped by then, else 1.16.0 for the later merge) and update `conformance/runner/runner.py`, `stub_cli.py`, the four `version` writers and the version tests in one commit |
| J-C-2 | Financing curve, extending D22 | The financing curve is the funding curve plus a cumulative spread `S(t)`, bootstrapped exactly from term repo quotes: `S(T_i) = ln(1 + R_i T_i) - Z(T_i) T_i`, quotes simple on the curve's year-fraction axis. Spreads and repo rates may be negative (specials); only `1 + R T <= 0` is `E_DOMAIN`. This **extends** D22 and does not change it: D22 (flat borrow and financing on the funding curve) still governs `eq.dividend.implied`, `eq.borrow.implied` and `eq.futures.basis`, whose goldens do not move. With one flat spread and one flat fee the new operations reproduce the D22 forward (property test in every build) |
| J-C-3 | Interpolation and coverage | Cumulative quantities (`Z(t) t`, `S(t)`, `B(t)`) are linear in `t` between knots, with the knot `(0, 0)`: flat forwards [Hagan-West06, raw interpolation]. No extrapolation: a query or maturity after the earliest last knot of the curves in use is `E_DOMAIN`, and a repo quote after the last funding knot is `E_DOMAIN` |
| J-C-4 | Stock borrow term structure | Quotes are term-average continuous fees `b_j >= 0` over `[0, T_j]`; `B(T_j) = b_j T_j` must not fall (else `E_DOMAIN`), so every forward fee is non-negative. Empty borrow arrays mean no borrow (`B = 0`, `borrow_fee` output `null`); the coverage then ignores borrow |
| J-C-5 | Equity forward with term financing | `C(t) = exp(-Z(t) t - S(t) + B(t))`; `F = (S_0 - sum A_i C(t_i)) / C(T)` over dividends with `0 < t_i <= T`, as C2 and `eq.forward.outright`. `carry = F - S_0`. `F <= 0` is `E_DOMAIN`. Bond carry on a term repo curve is not an operation in this lane (callers read `financing_rate` at the horizon and pass it to `repo.forward`) |
| J-C-6 | Liquidity curve design | Cost per unit, fraction of arrival price: `s + Y sigma (Q/(V h))^delta + z sigma sqrt(h/3)`. Square-root law [TLD11] at `delta = 1/2`, written in daily participation [AFTHL05]; defaults `Y = 1` (assumed, as stage H H-10), `delta = 1/2`, `z = 0`. `delta` in `(0, 1]`. Chosen over an FRTB liquidity-horizon curve because it is a cost curve in size and horizon that stage H's impact and Almgren-Chriss items can reuse directly; FRTB horizons are recorded as not built |
| J-C-7 | Timing risk | `z` standard deviations of the average price of an even (linear) liquidation over `h` days: continuous-time variance `sigma^2 h / 3` per unit squared [AC00]. Not the discrete `N`-slice variance |
| J-C-8 | Optimal horizon and stage H reuse | `h* = (2 delta a / b)^{1/(delta + 1/2)}` with `a = Y sigma (Q/V)^delta`, `b = z sigma / sqrt 3`; `null` outputs when `b = 0` or `Y = 0`; `h* = 0`, `c* = s` for `Q = 0`. Stage H must keep `exec.impact.sqrt(Q, V, sigma, Y)` equal to this curve's impact at `h = 1`, `delta = 1/2`, and should build its pre-trade cost estimate (H-17) on `liq.curve.cost` rather than a second formula |
| J-C-9 | Evidence | No free published worked example with fully stated inputs was found for either curve, and no free library implements them (QuantLib's spreaded curves interpolate zero spreads, not cumulative spreads). Goldens are hand derivations (marked `hand`, five financing and two liquidity cases) or reference-computed in mpmath from the spec text. Both curves are self-assessed: no outside library computes them |
