## Wave 1 confirmation rulings (2026-11-19)

| # | Point | Ruling |
|---|---|---|
| KR-15 | `M3` with a short position (corrects KR-7) | `M3 = T^3 abs(N) exp(-T min(y, y + h))`. The third derivative of `V(y) = N exp(-yT)` is `-T^3 N exp(-yT)`; its absolute value `T^3 abs(N) exp(-yT)` is largest at the smallest yield on the segment. KR-7 wrote `N`, which gives a negative "bound" when `N < 0`. Goldens are unchanged: idr_k-0005 (short 2-year leg) was already generated with `abs(N)` |
| KR-16 | Stage A mapping resolution (corrects KR-3) | A stage A record maps to `valid_from = event_time`, `valid_to = event_time + 1 s`, one step of the contract's whole-second instants. Still documented only, not an operation |
| KR-17 | The intraday bound in binary64 (completes KR-7) | The `bound` output is the exact-arithmetic Lagrange bound `sum_i abs(h)^3 M3_i / 6`, evaluated in binary64 with an exactly rounded sum. Derivation: Taylor's theorem with the Lagrange remainder gives `V(y + h) - V(y) - V'(y) h - V''(y) h^2 / 2 = V3(xi) h^3 / 6` (`V3` the third derivative) for some `xi` between `y` and `y + h`, so the remainder of one position is at most `abs(h)^3 T^3 abs(N) exp(-T xi) / 6 <= abs(h)^3 M3 / 6` (KR-15); over a book the position bounds are summed (no netting, since the `xi` differ). The binary64 comparison of the acceptance (`abs(estimate - revaluation) <= bound`) adds rounding of order `10 eps sum abs(N) exp(-yT) T abs(h)` against a bound of order `sum abs(N) exp(-yT) T^3 abs(h)^3 / 6`, so it is meaningful only when `T abs(h)` is well above `sqrt(60 eps)`, about 1e-7. The 1,000-move acceptance is therefore also checked at 50 digits (`oracle/python/check_stage_k_idr_moves.py`, output `oracle/IDR_K_MOVES_CHECK_W1.json`): zero exact violations in the Python and Java runs, binary64 rounding at most 2.3e-8 of the bound, smallest exact margin 0.62 of the bound. This closes the "idr bounds provisional" note of the blind record: the four golden bounds were filled to full precision by the oracle lane (mpmath, 50 digits), idr_k-0005 is filled and is not blind, and the blind check of the four bounds stays a check to 6 decimals |

## K-8c follow-up rulings (2026-11-19), written before the second acceptance run

The first acceptance run of `CN_RANNACHER_SMOOTHED` (`oracle/K8_ACCEPTANCE_W1.json`) failed acceptance 3 on 18 entries. The cause was found by separate refinement in time and in space (`program/K8_DIAGNOSIS.md`, measured). The two rulings below change the method and the reference grid. They do not change the 1% threshold, the default grid 201/100, the three judged cases, the order window 1.5 to 2.5 or the rule that picks the judged entries. Both were committed before any acceptance run of the revised method.

Numbering: KR-18 and KR-19 were first committed as KR-15 and KR-16 on branch `k-k8` on 2026-11-19 (commit c714dadd, before the second acceptance run in commit 8908ab3d) and renumbered at integration on branch `k-k8-ports`, because the wave 1 confirmation (branch `k-w1`) had already used KR-15 to KR-17. Only the numbers changed; the text is the one of c714dadd. Every citation in the K-8 files (spec, diagnosis, porting note, code comments, tests, `oracle/K8_ACCEPTANCE_W2.json`) was renumbered with it.

| # | Point | Ruling |
|---|---|---|
| KR-18 | `CN_RANNACHER_SMOOTHED`, revised definition | Three changes to the KR-8 method, each with its measured cause and its source. (a) **Curve term integrated exactly.** The scheme solves for `U(t,x) = V(t,x) exp(-int_0^t alpha)`, which removes `alpha(t)` from the operator; the curve enters only through `P(0,t)` at exercise and payment times. Cause: with `alpha` sampled at step ends, a curve node inside a time step (here 0.4986 years) gives a first-order error in the two neighbouring ladder entries (measured: time-only refinement at 401 nodes, order 1.00 on entries 1 and 2, 2.00 on every entry after the change). Source: the factor is the exact solution of the reaction term, which commutes with the rest of the operator (derived here; inferred). (b) **Exercise smoothing by a hat-weighted average with an end correction**, replacing the cell average. Node `i` takes `E_i` plus the average of `max(V - E, 0)` against the hat function on `[x_(i-1), x_(i+1)]`, `V - E` linear between nodes, plus a third-order correction in the cell that holds the crossing, followed by the stencil `1 - delta^2/6` so that nodes away from the crossing keep `max(V, E)`. Cause: a ladder entry is an exercise probability, so its data are a step, not a kink. A cell average is a first-order smoothing operator; for step data a second-order scheme needs a second-order one, whose transform vanishes to second order at the grid frequencies: the hat function [Kreiss, Thomee, Widlund, "Smoothing of initial data and rates of convergence for parabolic difference equations", *Comm. Pure Appl. Math.* 23 (1970) 241-259 (recalled, not read); Pooley, Vetzal, Forsyth 2003, sections 2.2 and 2.4, where the cell average is credited to that paper and the remark is made that averaged data may still have kinks (read 2026-11-19, https://cs.uwaterloo.ca/~paforsyt/report.pdf)]. The end correction removes the remaining term that depends on where the crossing sits in its cell (derived here; measured: space-only refinement on seven grids, error times `(nx-1)^2` constant to 2% with it, varying by a factor of 4 without it). (c) **Four implicit half steps** (the first two steps) after maturity and after each exercise date instead of two [Giles and Carter 2006, section 1 and Table 1: four half steps are the minimum that keeps the high-wavenumber error at or below second order for the value and its first two derivatives of both a call and a digital (read 2026-11-19, https://people.maths.ox.ac.uk/gilesm/files/giles_carter.pdf)]. The formulas are in `06-risk/bermudan-ladder-k8.md` version 0.2.0. The method name is kept: no golden of the first definition was ever published |
| KR-19 | K-8 reference grid | Acceptance 1 proposed QuantLib `tGrid` 2,000 and `xGrid` 801. QuantLib's engine applies the exercise `max` pointwise, so its bumped derivative carries the same grid-position noise this item is about. The reference is therefore taken at `tGrid` 8,000 and `xGrid` 3,201 (finer, never coarser), with the same two bumps (1e-4 and 5e-5 relative, central) and the same 0.1% agreement rule; an entry that fails the rule is reported as unresolved, as before. A bump-size study (eleven bumps from 1e-5 to 1.6e-2) is recorded next to the reference to show the plateau. The proposed 2,000/801 reference is also run and recorded, not used to judge. The choice of grid uses only QuantLib's own behaviour (plateau, agreement between its two grids), never the comparison with the method under test |
