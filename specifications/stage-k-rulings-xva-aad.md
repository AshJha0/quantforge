# Stage K rulings, item K-8 (AAD part): sensitivities of the valuation adjustments (KR-262 to KR-268): PROPOSED

Written 2026-11-20 by the lane `k-v1-aad`. **Status: PROPOSED**; the stage K coordinator confirms or amends them. Separate file so the branches merge without conflict. Spec: `06-risk/xva-aad-adjustments.md`. Plan 14.8 K-8: "AAD xVA sensitivities equal bump to 1e-8 relative".

**Relation to the K-8b spec lane (branch `k-xva-spec`, not merged here).** That lane proposed `xva.sens.aad` over seven operations (its KR-161, KR-162) and designed cases `aadx_k-0001` to `-0012`. Only `xva.adjustments.value` (G-41) exists on `k-v1`, so this lane implements that part, keeps the operation id `xva.sens.aad` and the `{operation, inputs, wrt}` request shape, and writes its goldens to a separate suite `aadadj_k` so that the other lane's `aadx_k` numbering stays free. `aadadj_k-0001` and `-0002` are that lane's `aadx_k-0001` and `-0002`; its error designs `aadx_ke-0001`, `-0002`, `-0003` are `aadadj_k-0018`, `-0022` and `-0017` (with `-0014` as the one-error form of `-0003`). Where this file and KR-161 differ (the reference, KR-265), this file says why.

| # | Point | Ruling |
|---|---|---|
| KR-262 | Operation and scope | `xva.sens.aad` takes `operation` (a string), `inputs` (an object) and optional `wrt` (an array of strings). In this version the only accepted `operation` is `xva.adjustments.value`; any other string, including the other six of KR-162 whose specs are not confirmed on `k-v1`, is an unlisted enum spelling, `E_SCHEMA`. `inputs` is read exactly as `xva.adjustments.value` reads its request (G-41: same keys, same types, same errors). Outputs: that operation's outputs (`cva`, `dva`, `fca`, `fba`, `fva`, and `mva`, `kva` when their inputs are given), computed by the same code, plus `gradient`: an object from each of those output names to an object from input key (KR-263) to the derivative. Adding an operation later is a minor change (contract "Versioning"). |
| KR-263 | Differentiated inputs, keys and units | Keys, in this order: `counterparty.hazard_rate`, `counterparty.hazard_buckets`, `counterparty.recovery`, `own.hazard_rate`, `own.hazard_buckets`, `own.recovery`, `discount_factors`, `ee`, `ene`, `funding.borrow_spread`, `funding.lend_spread`, then `im` and `im_spread` when `im` is given, then `capital` and `hurdle_rate` when `capital` is given. A profile key holds an array of one entry per bucket; the others hold a number. Every entry is the derivative per unit absolute change of the input: per 1.0 of hazard rate (per year), per 1.0 of recovery, per 1.0 of discount factor, per one currency unit of the profile point, per 1.0 of spread (decimal). Per basis point of a hazard or spread, multiply by 1e-4. A zero rate `z_i` with `D_i = e^(-z_i t_i)` has `d / d z_i = -t_i D_i d / d D_i` (stated, not output). **Bucket hazards** are not inputs of G-41: `hazard_buckets[j]` is the derivative with respect to the hazard of bucket `(t_(j-1), t_j]` of a piecewise-flat hazard curve, evaluated where every bucket equals the flat input, with survival `S(t_k) = exp(-sum_(j<=k) h_j (t_j - t_(j-1)))` (`t_0 = 0`), and with the overlap floor of FBA bucket `j` using `h_j` (KR-264). Their sum equals the flat entry up to rounding. Not differentiated: `times` (the grid) and `exclude_dva_overlap` (a flag). With `wrt`, each output's object holds only the listed keys, in the order above, whatever order `wrt` gives. |
| KR-264 | What is differentiated; kinks | The derivative of the computed G-41 formulas (as KR-161 and `aad-core.md`): the sums over buckets as written, survival `e^(-h t)` evaluated at the bucket ends, exposure at the bucket end. (a) `ene <= 0` on the domain, so `|ene_i| = -ene_i` and `d|ene_i| / d ene_i = -1`, also at `ene_i = 0` (the domain boundary; the derivative of the formula's only branch). (b) `ee`, recoveries, spreads, profiles and discount factors enter linearly; hazards through `exp`; at `h = 0` the entry is the derivative of the analytic formula (a one-sided limit from inside the domain, equal to the two-sided one of the formula). (c) The overlap floor of G-41, `s_l' = max(s_l - h_b (1 - R_b), 0)`, has a kink. The branch is decided on the binary64 value `x = s_l - h_b (1 - R_b)` the forward pass computes: `x >= 0` takes the linear branch (`d s_l' / d s_l = 1`, `d / d h_b = -(1 - R_b)`, `d / d R_b = h_b`), `x < 0` the zero branch (all 0). At `x = 0` exactly this is the one-sided derivative from above: a convention, as KR-161's `max(a, b)` takes `a` when `a >= b`, not a derivative. Golden `aadadj_k-0009` sits on the kink and pins the convention; `-0007` and `-0010` sit on the zero branch. |
| KR-265 | The bump reference and the acceptance | **Plain idea.** The plan asks that AAD equal bump-and-revalue to 1e-8 relative. A binary64 central bump is itself inexact: its rounding error is about `eps |f| / (h |x|)`, which for a small profile point (`ee_i = 1e-3` beside a CVA of 3, `h = 1e-4` relative) is about 3e-9 absolute against a derivative of 6e-3, a relative error near 1e-6. Such a bump cannot judge AAD at 1e-8. So the reference is the bump in 50-digit arithmetic. **Rule.** For each input `x` the reference is `(4 D(d/2) - D(d)) / 3` with `D(d) = (f(x + d) - f(x - d)) / (2 d)`, `d = 1e-12 max(1, |x|)`, `f` the G-41 formulas evaluated at 50 significant digits on the binary64 inputs, with the overlap branch of KR-264 held fixed. The functions are linear or exponential in each input, so the Richardson truncation is of order `d^4` times a bounded fifth derivative (below 1e-45 of the scale) and the rounding about `1e-50 |f| / d` (below 1e-37 of the scale): exact far below 1e-8. The oracle also evaluates the hand-derived closed-form adjoint at 50 digits and refuses to write a golden unless every entry agrees with the bump to 1e-30 of `max(1, |entry|)` (measured: all 13 value goldens agree). **Acceptance.** (A1, every build, every gradient entry of every value golden) `|AAD - ref| <= 1e-12 + 1e-10 max(|AAD|, |ref|)`, the golden's own tolerance (`tolerance_limit`, class `aad_sensitivity`). This implies the plan's bound in the form `|AAD - ref| <= 1e-8 max(1, |ref|)`, since `1e-12 + 1e-10 m <= 1e-8 max(1, m)` for every `m >= 0`. (A2, Python) the same bound on 1,000 seeded random requests (seed 20261120, 1 to 6 buckets, both overlap settings, optional `im` and `capital`), reference computed in the test with Python's `decimal` at 50 digits by the same rule. (A3, Python, reported not gated) the KR-161 binary64 Richardson bump (`h = 1e-4` relative) on the value goldens, with the largest gap recorded in the spec. KR-161's binary64 reference is kept for the operations whose 50-digit forward is not written (the other K-8b operations); for this operation it is replaced, because its own error can exceed the bound it judges. |
| KR-266 | Limits | At most 10,000 buckets: `times`, `discount_factors`, `ee`, `ene`, `im` and `capital` of `inputs` each hold at most 10,000 entries, else `E_LIMIT` (the KR-175 figure proposed by the K-8b spec lane), checked as step 2 of the order below. `wrt` needs no limit of its own: it holds at most the 15 distinct keys of KR-263, a longer list fails the duplicate rule. |
| KR-267 | Errors and their order | Order KR-230 / HR-122: (1) `E_SCHEMA`: `operation` missing or not a string or not `xva.adjustments.value`; `inputs` missing or not an object, or failing the G-41 request schema; `wrt` present and not an array of strings. (2) `E_LIMIT` (KR-266). (3) The F-2 finite rule: a non-finite Real anywhere in `inputs` is `E_DOMAIN`. (4) Structural `E_INPUT`: `wrt` empty, naming a key twice, naming a key not in KR-263, or naming `im`, `im_spread`, `capital` or `hurdle_rate` when the request does not carry it; then the G-41 structural checks (times, lengths, the `im` and `capital` pairs). (5) `E_DOMAIN`: the G-41 domain checks in G-41's order (counterparty, own, `ee`, `ene`). Two-error goldens `aadadj_k-0017` and `-0029` to `-0036` pin each adjacent pair of steps. |
